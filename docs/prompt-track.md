# Задача

Напиши музыкальный трек на **Strudel** (live-coding, JavaScript) в стиле
**{{СТИЛЬ}}**. Это не демо-скетч, а полноценный трек по нашим стандартам:
форма по секциям, автоматика, собственный пульт, проверки.

Доп. пожелания (могут быть пустыми): {{ТЕМП / ТОНАЛЬНОСТЬ / НАСТРОЕНИЕ / ДЛИНА}}
Доки стиля (если есть): {{ССЫЛКА_НА_ДОКИ_СТИЛЯ}}

# Что обязательно прочитать перед кодом

1. `docs/rules.md` — наши стилевые рамки и антипаттерны.
2. `docs/pitfalls.md` — грабли Strudel, на которых мы уже ломались
   (обязательно к соблюдению).
3. `docs/references.md` — индекс внешних источников (доки, примеры).
4. Доки стиля, если указаны: `docs/{{стиль}}/README.md` или ссылка выше.
5. Эталон структуры файла — `tracks/coldwave/03-cold-rooms-v3.js`
   (полный: пульт, TIMELINE, AUTOMATION, шум, грануляр). Простой пример —
   `tracks/coldwave/01-cold-rooms.js`. Для джаза/трип-хопа —
   `tracks/trip-hop/02-acid-jazz-v2.js`.

Если доков стиля нет — **сам найди 2–3 источника** (strudel.cc/learn/*,
GitHub-примеры из `docs/references.md`), выпиши темп, гармонию, ритм,
инструменты, микс и «чего в жанре не делают», и только потом пиши.

# Жёсткие требования

- Трек должен **звучать в оригинальном strudel.cc**. Запрещена «магия
  панели»: только нативные функции Strudel. Автоматика — через
  `arrange`/`saw.range` (`autoCurve`), секции — обычным кодом.
- Строки мини-нотации — **только через `m(...)`**: `note(m('d3 f3'))`,
  `s(m('bd ~ sd ~'))`.
- Никаких отрицательных литералов в `slider(...)` (значение уйдёт в `NaN`).
- Один тембр — **свои слайдеры**, не общий `vol` с другим инструментом.
- Один общий `roomsize` (`fx.reverb.size`) на все слои.
- Не вешай `distort`/`shape`/`crush`/`ftype('ladder')` на плотные партии
  (16-е, `seg(...)`): каждый такой контрол — worklet на событие. Бюджет —
  до ~150 worklet/с (`npm run cpu`).
- `supersaw` — 7 осцилляторов на голос: не стакай его в аккордах с `seg(8)`.
- Не добавляй `chord()`/`voicing()` без нужды: в node-проверке их нет,
  `verify` не сможет проверить такой трек. Пиши явные ноты.
- Даб/регги — только если стиль прямо просит.

# Стандарт файла

Один файл `tracks/{{стиль}}/NN-{{slug}}.js`:

1. **Шапка-комментарий**: BPM, жанр, состав, форма, ссылка на доки стиля.
2. `setcpm(BPM / 4)`.
3. Блок `samples({...})` — только если нужны сэмплы; CDN jsDelivr или
   локальные пути. Никаких `raw.githubusercontent` (часто 503).
4. `// @switches name=variant1,variant2,...` — если у трека есть
   переключатели (панель их подписывает); сами переключатели — обычные
   top-level `slider(0,0,N,1)` с `min 0` и `step 1`.
5. **Пульт** — дерево:
   ```js
   const instruments = {
     drums: { kick: { name: 'Kick', vol: slider(0.4, 0, 0.8, 0.01), cut: slider(...) } },
     low:   { bass: { name: 'Bass', vol: ..., cut: ... } },
     keys:  { pad:  { name: 'Pad',  vol: ..., cut: ..., atk: ... } },
     fx:    { reverb: { size: slider(3, 1, 8, 0.5) } },
   }
   const { drums, low, keys, fx } = instruments
   ```
6. **Таймлайн секций**: массив `{ at, len, name, values }` + функция
   `tlCurve(key)`/`tlOr(key)` (как в эталоне) и `song`-гейт для SONG/LOOP.
   `tlCurve` несёт последнее значение вперёд — ставь `0` явно.
   Раздели материал и ритм: `figures` (ноты, один источник правды),
   `grooves` (ритмы по слотам: kick/snare/hat/bass…) и `autoSwitch(key, knob)`
   = «SONG → секция / LOOP → ручка / HOLD → секция». На каждое семейство
   (`mode`, `gtr`, `arp`…) — свой свитч и свой ключ в секциях.
   Сделай переключатель режима **трёхпозиционным** (имя любое) и объяви роли
   маркерами: `// @transport play` (0 = jam, 1 = timeline, max = HOLD) и
   `// @holdBar holdBar` (такт снимка). Панель не знает имён трека.
   0 = LOOP (без TIMELINE, все слои), 1 = SONG (по форме), 2 = HOLD (состояние
   секции под `holdBar`, автоматика заморожена). Панель переключает и двигает
   `holdBar` сама; без этой ветки hold-режим не заработает.
7. **AUTOMATION**: `[{ path, points: [[bar, mult], ...] }]` + `autoCurve`,
   который строит `arrange` из `pure`/`saw.range`. Префикс — `pure(1)`.
8. **Дорожки** — по одной на инструмент, `$: ...` с цепочкой
   `gain(vol.mul(tlOr('lane')))`, фильтром, огибающей, `room`, `filter(audible)`.
9. Закомментируй ключевые решения (почему такой срез, зачем `seg`, где
   входит слой) — коротко, по делу.

# Музыкальные требования к стилю

Перед кодом выпиши (и соблюдай) для {{СТИЛЬ}}:
- темп и размер, тип грува;
- гармония: тональность/лады, аккорды, как часто меняются;
- ритм: бочка, снейр/клэп, хэты, перкуссия;
- бас: регистр, артикуляция, срез;
- синты/гитары: тембры, огибающие, эффекты;
- аранжировка: 4–7 секций, что входит/выходит, где пустота;
- микс: тёмный/яркий верх, реверб/дилей, что не забивает;
- **чего избегать** в этом жанре (из доков/источников).

Ключевое правило: **не заполнять**. Пустота и паузы — часть музыки; убирать
слой между секциями сильнее, чем добавлять новый.

# Проверка перед сдачей (обязательно)

Прогоняй и чини, пока не будет exit 0:

```bash
npm run verify -- tracks/{{стиль}}/NN-{{slug}}.js
npm run gains  -- tracks/{{стиль}}/NN-{{slug}}.js
npm run cpu    -- tracks/{{стиль}}/NN-{{slug}}.js
npm run tension -- tracks/{{стиль}}/NN-{{slug}}.js   # если есть // @roots
```

- `verify` — парсинг и реальная сетка 1/16, число дорожек/ударов/слайдеров.
- `gains` — трек должен глушиться в ноль; иначе ищи `stut`/`echo` после `gain`.
- `cpu` — worklet/с; бюджет ~150/с. Помни: он смотрит первые 8 тактов, слои
  из поздних секций проверяй отдельно.
- `tension` — только если есть `// @roots`; это детектор случайной грязи,
  осознанный диссонанс можно оставить.

В финальном ответе: путь к файлу, BPM/тональность, список секций, цифры
`verify`/`cpu`, и что осталось на твой вкус.

# Сдача

- Создай файл по пути выше.
- Добавь запись о треке в `README.md` (раздел трека: стиль, BPM, состав,
  форма, проверки).
- Если ты добавил новый жанр — создай/дополни `docs/{{стиль}}/README.md`
  (плейбук: звук, ритм, бас, синты, аранжировка, микс, ошибки) и допиши
  ссылку в `docs/references.md`.
- Не добавляй комментарии-заглушки, `TODO` и `...` в код.

# Если что-то непонятно

Не угадывай молча: задай 2–3 коротких вопроса (темп, тональность, длина,
обязательные/запрещённые инструменты) и только потом пиши код.

Когда промпт уходит в интернет, замени внутренние ссылки на прямые URL:

| Внутренняя ссылка | Заменить на |

| `docs/pitfalls.md` | ссылка на опубликованный `pitfalls.md` |
| `docs/references.md` | ссылка на опубликованный `references.md` |

Команды `npm run ...` при публикации либо оставь как «если есть окружение
репозитория», либо убери и замени на ручную проверку в strudel.cc.
