1. Цикл = такт

В Strudel всё живёт в циклах. В наших треках цикл = один такт (4/4), потому что стоит setcpm(BPM / 4) или setcpm(160/4). Если поменять на setcpm(BPM), цикл станет 4 такта. Отсюда все «на такт» и «раз в 4 такта». 

setcpm(140 / 4)   // 140 BPM, 1 цикл = 1 такт

2. Mini-notation: ритм и группировка

ЗаписьЧто делает
a b cТри события внутри одного цикла, поровну.
~Пауза (rest).
a*4Повторить 4 раза за цикл (ускорить).
a/2Замедлить: событие на 2 цикла.
[a b]Сгруппировать несколько шагов в один элемент.
[a,b]Одновременно (аккорд).
<a b>Чередование: по одному элементу за цикл.
a@2Длительность ×2 (вес шага).
a!Повторить событие.

Ключевое: пробел = последовательность, запятая = одновременность, угловые скобки = переключение по циклам. 

note("d5 ~ f5 ~ a5 ~ f5 ~")       // 8 восьмых в одном такте, с паузами

note("<d4 f4 a4>")               // такт 1: d4, такт 2: f4, такт 3: a4

note("<[c4 ~ ~ ~] [g3 ~ b3 ~]>")  // две фразы по 4 шага, меняются по тактам
Квадратные скобки в <...> нужны, чтобы чередовать не отдельные ноты, а целые фразы. Без скобок <c4 ~ ~ ~ g3 ~ b3 ~> — это 8 циклов по одному событию.

3. Аккорд, арпеджио и почему «не звучит как аккорд»

[c4 ~ ~ ~] — это последовательность (c4, потом три паузы), а не аккорд. Аккорд — запятые: 

note("[c4,e4,g4]")                 // три ноты одновременно, весь такт
note("[a3 c4 ~ e4]")               // последовательность: a3, c4, пауза, e4
note("<[c4,e4,g4] [g3,b3,d4]>")  // аккорд меняется по тактам

Если слышишь арпеджио — значит внутри группы стоят пробелы, а не запятые. Для аккордового символа есть chord("Cmaj7"), но с ручными нотами проще и предсказуемее.

4. note / s / sound: питч и источник звука

  • note("c4 e4") — задаёт высоту.
  • s("bd*4") — источник: сэмпл, синтезатор или шум.
  • sound — тот же s, просто полная запись.
s("bd*4")                          // сэмпл kick, 4 удара
note("d2*8").sound("sawtooth")     // пила играет ноту d2
note("d2*8").s("sawtooth")         // то же самое

Источники: sine, triangle, square, sawtooth, supersaw, шумы white / pink; сэмплы — bd, sd, hh, oh, cp, rim, sh (если загружены через samples(...)).

5. Слайдеры: const и inline

Синтаксис: slider(value, min, max, step) — четыре числа.

const cut = slider(810, 100, 5000, 10)

// в const — один слайдер, можно переиспользовать по имени
note("c2*8").s("sawtooth").lpf(cut)

// inline — отдельная ручка прямо в цепочке, тоже живая
note("c5 e5 g5").s("sawtooth").lpf(slider(3000, 300, 9000, 20))
constinline
Имя в UIесть (cut)техническое
Переиспользоватьданет, каждый вызов — своя ручка
Для быстрых набросков—удобно
Первый аргумент — только литерал-число. Выражения (600 * 2) не поддерживаются: панель перезаписывает именно это число. Если слайдер «не рисуется», смотри консоль: чаще всего ReferenceError (например, используешь leadCut, который не объявлен).

6. Фильтры и катофф

.lpf(600)        // low-pass cutoff, Гц
.lpq(8)          // resonance
.hpf(200)        // high-pass
.lpenv(3)        // огибающая фильтра в октавах
.lpa(0.004)      // attack огибающей
.lpd(0.12)       // decay
.lpsustain(0.1)  // sustain

У баса катофф часто держат низко (у нас правило ≤80 по умолчанию), а «яркость» дают огибающей (lpenv), а не ручкой. Медленный LFO на срез — lpdepth/lpsync.

Транс-синты: реальные значения в Strudel

lpf — Гц, lpq — реальный Q (0–50), lpenv — глубина в октавах. Совет из DAW «cutoff 400–1000, Q 12–15» не переносится 1:1: в Strudel Q 12–15 кричит, а psy top-бас — это не то же самое, что правило «sub ≤80».

  • lpf: sub 40–80; top-бас 300–600; acid base 80–200; lead 800–2000; pad 200–600; хэты 6k–12k.
  • lpq: 0–4 музыкально; 5–15 агрессивно; 12–15 — крик.
  • lpenv: 1–4 обычно; acid 3–5 от низкого base.
  • lpd/lps: acid 0.05–0.15 с / 0–0.2; бас 0.03–0.08 с / 0.
  • ftype: ladder для 303 (один worklet на ивент), 24db для баса, 12db для мягкого лида.
  • roomsize 0–10, room 0–1, delaytime в секундах, delayfeedback 0–1, distort 0–10 (0–2 достаточно).

303 — это низкий базовый срез + глубокая огибающая, а не высокий base + мелкая огибающая: 

.lpf(120)          // Гц: низкий base
.lpq(4)            // Q: музыкально, не 15
.lpenv(4.5)        // октавы: глубоко
.lpa(0.002)        // секунды
.lpd(0.055)        // секунды
.lpsustain(0.05)   // 0–1
.ftype('ladder')   // характер 303; один worklet на ивент
.decay(0.055).sustain(0.1).release(0.03)

Бас: .lpf(410).lpq(2).lpenv(3).lpd(0.05).ftype('24db'). Лид: .lpf(1280).lpq(2).lpenv(2).lpd(0.12).

Медленное LFO на фильтр

Два способа. Первый — LFO поверх базового среза (ручка остаётся базой): 

.lpf(600).lpq(8)
.lpdepth(1.2)     // глубина: множитель к lpf (600 ± 1.2×600)
.lpsync(0.25)     // скорость: 0.25 цикла LFO за цикл = 1 качель на 4 такта
.lpdc(0)          // униполярно: только открывает вверх, не режет ниже базы

lpsync(n) — n качелей за цикл (наш цикл = такт); lprate(hz) — в герцах, не привязано к темпу. lpdc(0) убирает ход в минус, lpdepth задаёт амплитуду.

Второй — явный сигнал вместо базового среза (точные границы): 

.lpf(sine.slow(8).range(250, 2200))  // один проход LFO за 8 тактов

sine.slow(8) — один цикл синуса на 8 циклов трека; range(min, max) задаёт низ и верх среза.

Если 3300 — это максимум, а LFO должен идти только вниз, проще вычитать сигнал, чем бороться со знаком lpdc: 

.lpf(3300 - sine.range(0, 2500).slow(8))
// диапазон 800…3300, выше 3300 не уходит

Или с базой-слайдером: .lpf(cut.sub(sine.range(0, 2500).slow(8))).

3300 - sine.range(...) — это обычная JS-арифметика, а не паттерн: получается NaN, и фильтр замолкает. Арифметика должна быть паттерновой: pure(3300).sub(sine.range(0, 2500).slow(8)) или sine.range(800, 3300).slow(8).

7. stack, $: и слои

stack(
  s("bd*4").gain(0.8),
  s("hh*16").gain(0.3),
  note("c2*8").s("sawtooth").lpf(600).gain(0.5)
)

stack играет всё одновременно. $: — то же, но несколькими независимыми блоками (удобно для микшера и отдельных дорожек). Оба варианта валидны; stack компактнее.

8. Форма: arrange и TIMELINE

Простейшая форма — arrange (длина в тактах, паттерн):

arrange(
  [8,  stack(kick, hats, pad)],
  [16, stack(kick, bass, hats, pad, lead)],
  [8,  stack(pad, air)]
)

В панели форма рисуется, если есть const TIMELINE = [...]: секции { at, len, name, values }, а values — множители к громкостям через tlCurve('слой'). 0 = слой молчит. 

const TIMELINE = [
  { at: 0, len: 8, name: 'INTRO', values: { kick: 1, bass: 0 } },
  { at: 8, len: 16, name: 'DROP', values: { kick: 1, bass: 1 } },
]
.gain(drums.kick.vol.mul(tlCurve('kick')))

9. Грануляр: striate / chop

s('quote').striate(24)   // разбить на 24 гранулы за цикл
s('quote').chop(16)      // нарезать на 16 кусков по порядку
.begin(0.1).end(0.8)     // играть только часть сэмпла
.speed(0.8)              // скорость
.clip(0.4)               // короче гранула

striate — «облако» осколков, chop — последовательная нарезка. begin/end задают окно в сэмпле (0…1), это удобно, чтобы не тянуть всю цитату.

10. Реверб, дилей, jux

.room(0.6).roomsize(10)          // send и размер
.delay(0.4).delaytime(0.375).delayfeedback(0.5)

delaytime — в циклах, не в секундах: 0.375 = ⅜ такта (триольная восьмая), 0.25 = ¼.

jux(f) — стерео-трюк: оригинал влево, f(паттерн) вправо. jux(rev) = правый канал играет цикл назад. juxBy(0.2, rev) — то же, но ширина меньше. Помни: это удваивает голоса (и нагрузку).

Один реверб на несколько каналов

room() — это send, а не вставка. Сам реверб создаётся один на orbit (по умолчанию orbit 0): все $: с .room() на этом orbit шлют в один и тот же reverbNode. Поэтому 18 каналов stack(...).room(...) — это не 18 ревербов, а один. 

// один реверб на весь стек — экономно
stack(kick, perc).room(0.6).roomsize(10)

// разные roomsize на одном orbit → impulse response пересчитывается
// разные orbit → отдельные reverb/delay-шины
stack(a.room(.2).orbit(1), b.room(.8).orbit(2))

Дорого не число .room(), а размер roomsize (длина impulse response), смена roomsize на лету (реверб пересчитывается) и отдельные orbit. Держи один roomsize на трек; orbit добавляй, только если реально нужен другой простор или дилей.

11. Бочка: пропуски, «и» 4-й, every/mask

Основной рисунок:

s('bd').struct('x*4')          // 4-on-floor

Пропуски: либо перестроить такт, либо заглушить слой:

// иногда (12%) такт превращается в «~ ~ x ~»
s('bd').struct('x*4').sometimesBy(0.12, (x) => x.struct('~ ~ x ~'))

// убрать 10% ударов, не меняя сетку
s('bd').struct('x*4').degradeBy(0.1)

«И» 4-й доли — шаг 14 на 16-сетке. Дополнительный удар каждый 4-й такт: 

$: s('bd')
  .struct('~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ x ~')
  .mask('<0 0 0 1>')   // 3 такта тишины, 4-й — играет

every(4, fn) применяет функцию к каждому 4-му циклу, но заменяет рисунок на этом такте; чтобы «добавить», нужен отдельный слой с mask или stack.

12. LOOP / SONG

// @switches song=loop,song
const song = slider(0, 0, 1, 1)
const songGate = song.fmap((v) => (v > 0.5 ? 1 : 0))
const loopGate = song.fmap((v) => (v > 0.5 ? 0 : 1))
const tlOr = (key, loopLevel = pure(1)) =>
  tlCurve(key).mul(songGate).add(loopLevel.mul(loopGate))

.gain(drums.kick.vol.mul(tlOr('kick')))       // LOOP — 1, SONG — по таймлайну
.gain(vox.quote.vol.mul(tlOr('vox', pure(0)))) // в LOOP выключен

LOOP игнорирует TIMELINE и играет постоянный микс; SONG идёт по форме.

13. Сэмплы и почему «не грузится»

if (typeof samples === 'function') {
  samples({ bd: ['bd/11_bd_mot4i.wav'] }, 'https://cdn.jsdelivr.net/gh/tidalcycles/uzu-drumkit@main/')
  samples({ quote: ['samples/de-quote/kafka.wav'] }, './')
}
  • raw.githubusercontent.com часто отдаёт 503 — часть сэмплов молчит. jsDelivr или локальные файлы надёжнее.
  • Проверь консоль/Network: 404/503 = сэмпл, а не ритм.
  • В node-проверках samples() нет — поэтому вызов под typeof.
