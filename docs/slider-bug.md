# Баг слайдеров в strudel.cc: ползунок откатывается и портит код

Проверено 2026-11-12 на живом https://strudel.cc (headless Chromium + CDP), на файле
`tracks/techno/03-dub-v2.js`. Баг **не в наших треках** — он в виджете слайдера
самого редактора. Наши файлы при этом чистые: `npm run verify` и `npm run doubles`
проходят, конфликта ID нет (ID уникальны, это смещения в тексте).

## Симптомы (как это выглядит руками)

- Поднял слайдер, ушёл скроллом вниз/вверх — ползунок снова на старом значении
  (часто на нуле), хотя звук играет с поднятой громкостью.
- После этого тянешь его ещё раз — значение превращается в мусор
  (`0.8.55`), и трек перестаёт запускаться с `SyntaxError`.
- «Слайдер не реагирует» — то же самое: виджет показывает старое значение,
  а `sliderValues` уже другое.

## Воспроизведение (дословный вывод теста)

Слайдер `kickVol = slider(0, 0, 1.4, 0.01)`, позиция в тексте `from = 2450`:

```
старт:        " slider(0, 0, 1.4, 0.01) // бо"
драг 0 → 0.55 " slider(0.55, 0, 1.4, 0.01) //"     ← код верный
скролл ↓↑     DOM ползунка: value = "0"            ← а в коде 0.55
драг → 0.8    " slider(0.8.55, 0, 1.4, 0.01) "     ← код испорчен
драг → 0.2    " slider(0.2.8.55, 0, 1.4, 0.01"
Ctrl+Enter    SyntaxError, line 51, column 28      ← трек мёртв
```

## Причина: три строки в `@strudel/codemirror/slider.mjs`

```js
eq() { return false }                          // 21: DOM пересоздаётся при любом рендере

toDOM() {
  slider.originalValue = this.value;           // 34: this.value — значение НА МОМЕНТ ЗАПУСКА
  slider.value = slider.originalValue;         // 37: ползунок встаёт на него же
}

slider.addEventListener('input', (e) => {
  const to = slider.from + slider.originalValue.length;   // 47: длина берётся из originalValue
  this.view.dispatch({ changes: { from: slider.from, to, insert: next } });
  ...
  window.postMessage({ type: 'cm-slider', value: Number(next), id: getSliderID(slider.originalFrom) });
});
```

Цепочка:

1. Драг переписывает число в тексте и обновляет `originalValue` **на DOM-узле**.
   Объект виджета (`this.value`) при этом не меняется — он застыл на значении
   из последнего `Ctrl+Enter`.
2. `eq() { return false }` → CodeMirror пересоздаёт DOM-узел при каждом
   пере-рендере: скролл, возврат во вьюпорт, пересборка декораций после запуска.
   Новый узел берёт `this.value`, то есть **старое** значение. Ползунок визуально
   откатывается.
3. Следующий драг считает длину заменяемого куска от **старого** `originalValue`.
   Если число в тексте уже другой длины (`0` → `0.55`), замена съедает не то
   количество символов: остаётся хвост (`0.8.55`) или съедается запятая
   (`slider(0.45 0, 0.5, …)`). Это уже синтаксическая ошибка.

Звук при этом не врёт: живое значение лежит в `sliderValues[id]`, куда драг
пишет через `postMessage`. Поэтому «ползунок на нуле, а бас орёт» — нормальная
картина этого бага.

Почему `Ctrl+Enter` лечит: при запуске `afterEval` заново строит виджеты из
конфигов транспайлера, `value` берётся из текста кода, `sliderValues`
пересинхронизируется. Всё сходится — до следующего скролла.

## Рабочие правила (что делать руками)

- **Перед тем как тянуть слайдер — `Ctrl+Enter`.** Это единственный способ
  гарантировать, что `originalValue` совпадает с текстом. Стоит одно нажатие.
- **Если ползунок выглядит «сброшенным» — не тяни его.** Сначала `Ctrl+Enter`.
  Драг по рассинхронизированному виджету и есть то, что портит код.
- **Не скроллить во время игры.** Держи блок слайдеров в одном экране: пока
  узлы не пересоздаются, драги безопасны. Микшер в `03-dub-v2` для этого и
  вынесен наверх.
- **Код испорчен (`0.8.55`)?** Не запускай — сначала руками верни число.
  `Ctrl+Enter` на испорченном тексте даст `SyntaxError` и остановит трек.

## Ширина слайдера: 64px можно перебить

Виджет ставит ширину инлайном (`slider.style = 'width:64px; …'` в `toDOM()`), но
это обычный инлайн-стиль без `!important`, поэтому любое правило с `!important`
его перебивает. Замерено на живом strudel.cc:

| ширина | что происходит |
|--------|----------------|
| 64px (по умолчанию) | ~0.6 px на шаг 0.01 — попасть в значение мышкой почти нельзя |
| 160px | работает, вёрстка не едет |
| 180px | работает, `scrollWidth` не вырос (832 → 832) — самая длинная строка и так шире окна |
| 320px | работает, но `scrollWidth` 832 → 950: строки со слайдерами начинают лезть вправо |

**Вариант 1 — строкой в файле трека.** `document` в eval доступен (проверено:
ширина реально стала 180px). Строка идемпотентна, повторный `Ctrl+Enter` второй
`<style>` не добавит:

```js
// ширина слайдера: виджет рисует 64px инлайном, перебиваем !important
if (typeof document !== 'undefined' && !document.getElementById('slider-w')) {
  const st = document.createElement('style')
  st.id = 'slider-w'
  st.textContent = '.cm-slider input { width: 180px !important; }'
  document.head.appendChild(st)
}
```

Минус: это побочный эффект в музыкальном файле — не для «чистых» версий трека.
Рабочий пример — `tracks/techno/04-dub-v3.js` (там же и оговорка про кавычки:
транспайлер оборачивает в `m()` двойные кавычки и бэктики, поэтому CSS-правило
собирается в одинарных через конкатенацию).

**Вариант 2 — снаружи, один раз на страницу.** Stylus / Stylebot / любой
инжектор CSS:

```css
.cm-slider input { width: 180px !important; }
```

Треки остаются чистыми, но на новом браузере/профиле правило надо поставить снова.

**Точные значения — не мышкой.** Клик по слайдеру и `←` / `→` дают ровно один
шаг: `input` событие летит то же, но DOM-узел не пересоздаётся, поэтому это ещё
и самый безопасный способ (не попадает в баг с длиной числа).


## Что можно починить у себя

Синтаксисом — ничего: длина строки значения меняется у любого дробного слайдера
(`0` → `0.55`), а `slider()` не умеет фиксированную длину записи.

**А вот из самого трека — можно, и это работает.** Виджет хранит состояние не
только в себе: `from`, `originalFrom` и `originalValue` лежат прямо на
`<input>`, а запись в документ считается как
`to = slider.from + slider.originalValue.length`. Значит достаточно, чтобы
`originalValue` всегда совпадал с тем, что реально написано в коде — и портить
станет нечего.

```js
if (typeof document !== 'undefined' && !window.__sliderSync) {
  const syncSliders = () => {
    const m = window.strudelMirror
    if (!m || !m.editor) return
    const doc = m.editor.state.doc
    for (const el of document.querySelectorAll('.cm-slider input')) {
      if (typeof el.from !== 'number') continue
      const t = doc.sliceString(el.from, el.from + 24).match(/^-?\d+(?:\.\d+)?/)
      if (!t) continue
      if (el.originalValue !== t[0]) el.originalValue = t[0]  // длина для замены
      if (Number(el.value) !== Number(t[0])) el.value = t[0]  // сам ползунок
    }
  }
  window.__sliderSync = setInterval(syncSliders, 200)
  document.addEventListener('scroll', () => requestAnimationFrame(syncSliders), true)
  document.addEventListener('pointerdown', syncSliders, true)
}
```

Три точки запуска, каждая по делу:

- `pointerdown` — за мгновение до драга, чтобы длина замены была верной;
- `scroll` + `rAF` — CodeMirror пересоздаёт DOM за вьюпортом, новый узел
  приходит со старым значением; чиним в следующем кадре;
- `setInterval` — страховка на случай, если пере-рендер случился без скролла.

В документ заплатка НЕ пишет: звук и так идёт через `postMessage`, а id слайдера
считается от `originalFrom`, который мы не трогаем. То есть она чинит только
показания ползунка и длину замены — ровно две вещи, которые врут.

Проверено вживую (`npm run live`) на одном и том же сценарии «драг → уехать из
вьюпорта → вернуться → драг ещё раз»:

| файл | в коде | ползунок | итог |
|---|---|---|---|
| `05-deep-dub.js` (без заплатки) | `2` | `0` | РАССИНХРОН |
| `06-deep-dub-v2.js` (с заплаткой) | `3` | `3` | ок |

Отдельным тестом на длинном файле: без заплатки второй драг даёт `0.62` вместо
`0.6` (заменились 3 символа из 4); с заплаткой — `0.6`.

Ограничение: заплатка живёт, пока страница не перезагружена, и работает только
в редакторе strudel.cc (`window.strudelMirror`). В `@strudel/web` её нет — там
и слайдеров таких нет.

документа (`view.state.doc.sliceString(this.from, this.to)`) вместо `this.value`.
