1. Cycle = bar

In Strudel everything lives in cycles. In our tracks a cycle = one bar (4/4), because the track has setcpm(BPM / 4) or setcpm(160/4). If you change it to setcpm(BPM), the cycle becomes 4 bars. This is where all the "per bar" and "once every 4 bars" comes from. 

setcpm(140 / 4)   // 140 BPM, 1 cycle = 1 bar

2. Mini-notation: rhythm and grouping

NotationWhat it does
a b cThree events inside one cycle, evenly spaced.
~Rest.
a*4Repeat 4 times per cycle (speed up).
a/2Slow down: one event over 2 cycles.
[a b]Group several steps into one element.
[a,b]Simultaneously (a chord).
<a b>Alternation: one element per cycle.
a@2Duration ×2 (step weight).
a!Repeat the event.

The key: space = sequence, comma = simultaneity, angle brackets = switching by cycle. 

note("d5 ~ f5 ~ a5 ~ f5 ~")       // 8 eighths in one bar, with rests

note("<d4 f4 a4>")               // bar 1: d4, bar 2: f4, bar 3: a4

note("<[c4 ~ ~ ~] [g3 ~ b3 ~]>")  // two 4-step phrases, changing per bar
The square brackets inside <...> are needed to alternate whole phrases rather than individual notes. Without brackets, <c4 ~ ~ ~ g3 ~ b3 ~> is 8 cycles with one event each.

3. Chord, arpeggio, and why it "doesn't sound like a chord"

[c4 ~ ~ ~] is a sequence (c4, then three rests), not a chord. A chord is commas: 

note("[c4,e4,g4]")                 // three notes at once, the whole bar
note("[a3 c4 ~ e4]")               // a sequence: a3, c4, rest, e4
note("<[c4,e4,g4] [g3,b3,d4]>")  // the chord changes per bar

If you hear an arpeggio, it means the group contains spaces, not commas. For a chord symbol there is chord("Cmaj7"), but with hand-written notes it is simpler and more predictable.

4. note / s / sound: pitch and sound source

  • note("c4 e4") — sets the pitch.
  • s("bd*4") — the source: sample, synth or noise.
  • sound — the same as s, just the full spelling.
s("bd*4")                          // kick sample, 4 hits
note("d2*8").sound("sawtooth")     // the saw plays note d2
note("d2*8").s("sawtooth")         // the same thing

Sources: sine, triangle, square, sawtooth, supersaw, the noises white / pink; samples — bd, sd, hh, oh, cp, rim, sh (if they are loaded via samples(...)).

5. Sliders: const and inline

Syntax: slider(value, min, max, step) — four numbers.

const cut = slider(810, 100, 5000, 10)

// as a const — one slider, reusable by name
note("c2*8").s("sawtooth").lpf(cut)

// inline — a separate knob right in the chain, also live
note("c5 e5 g5").s("sawtooth").lpf(slider(3000, 300, 9000, 20))
constinline
Name in the UIpresent (cut)technical
Reusableyesno, each call is its own knob
For quick sketches—handy
The first argument must be a literal number. Expressions (600 * 2) are not supported: the panel rewrites exactly this number. If a slider "does not draw", check the console: most often it is a ReferenceError (for example, you use leadCut without declaring it).

6. Filters and cutoff

.lpf(600)        // low-pass cutoff, Hz
.lpq(8)          // resonance
.hpf(200)        // high-pass
.lpenv(3)        // filter envelope in octaves
.lpa(0.004)      // envelope attack
.lpd(0.12)       // decay
.lpsustain(0.1)  // sustain

For a bass, the cutoff is often kept low (our default rule is ≤80), and the "brightness" comes from the envelope (lpenv) rather than the knob. A slow LFO on the cutoff — lpdepth/lpsync.

Trance synths: actual Strudel values

lpf is Hz, lpq is a real Q factor (0–50), lpenv is depth in octaves. A DAW guide saying "cutoff 400–1000, Q 12–15" does not translate 1:1: in Strudel Q 12–15 screams, and a psy top bass is not the same as the ≤80 sub-bass rule.

  • lpf: sub 40–80; top bass 300–600; acid base 80–200; lead 800–2000; pad 200–600; hats 6k–12k.
  • lpq: 0–4 musical; 5–15 aggressive; 12–15 is a scream.
  • lpenv: 1–4 typical; acid 3–5 from a low base.
  • lpd/lps: acid 0.05–0.15 s / 0–0.2; bass 0.03–0.08 s / 0.
  • ftype: ladder for 303 (one worklet per event), 24db for bass, 12db for soft leads.
  • roomsize 0–10, room 0–1, delaytime seconds, delayfeedback 0–1, distort 0–10 (0–2 is plenty).

A 303 is a low base cutoff + deep filter envelope, not a high base + tiny envelope: 

.lpf(120)          // Hz: low base
.lpq(4)            // Q: musical, not 15
.lpenv(4.5)        // octaves: deep
.lpa(0.002)        // seconds
.lpd(0.055)        // seconds
.lpsustain(0.05)   // 0–1
.ftype('ladder')   // 303 character; one worklet per event
.decay(0.055).sustain(0.1).release(0.03)

Bass: .lpf(410).lpq(2).lpenv(3).lpd(0.05).ftype('24db'). Lead: .lpf(1280).lpq(2).lpenv(2).lpd(0.12).

Full psytrance playbook, riffs, FX and anti-patterns: docs/psytrance/README.en.md.

Slow LFO on the filter

Two ways. The first — an LFO on top of the base cutoff (the knob remains the base): 

.lpf(600).lpq(8)
.lpdepth(1.2)     // depth: multiplier on lpf (600 ± 1.2×600)
.lpsync(0.25)     // speed: 0.25 LFO cycles per cycle = 1 sweep per 4 bars
.lpdc(0)          // unipolar: only opens upward, never cuts below the base

lpsync(n) — n sweeps per cycle (our cycle = a bar); lprate(hz) — in hertz, not tied to tempo. lpdc(0) removes the downward swing, lpdepth sets the amplitude.

The second — an explicit signal instead of a base cutoff (exact bounds): 

.lpf(sine.slow(8).range(250, 2200))  // one LFO pass per 8 bars

sine.slow(8) — one sine cycle over 8 track cycles; range(min, max) sets the low and high cutoff.

If 3300 is the maximum and the LFO should only go down, it is easier to subtract the signal than to fight the sign of lpdc: 

.lpf(3300 - sine.range(0, 2500).slow(8))
// range 800…3300, never goes above 3300

Or with a slider base: .lpf(cut.sub(sine.range(0, 2500).slow(8))).

3300 - sine.range(...) is ordinary JS arithmetic, not a pattern: you get NaN, and the filter goes silent. The arithmetic must be pattern-based: pure(3300).sub(sine.range(0, 2500).slow(8)) or sine.range(800, 3300).slow(8).

7. stack, $:, and layers

stack(
  s("bd*4").gain(0.8),
  s("hh*16").gain(0.3),
  note("c2*8").s("sawtooth").lpf(600).gain(0.5)
)

stack plays everything at once. $: does the same but with several independent blocks (handy for a mixer and separate tracks). Both are valid; stack is more compact.

8. Form: arrange and TIMELINE

The simplest form is arrange (length in bars, pattern):

arrange(
  [8,  stack(kick, hats, pad)],
  [16, stack(kick, bass, hats, pad, lead)],
  [8,  stack(pad, air)]
)

In the panel the form is drawn if there is a const TIMELINE = [...]: sections { at, len, name, values }, and values are multipliers on the volumes via tlCurve('layer'). 0 = the layer is silent. 

const TIMELINE = [
  { at: 0, len: 8, name: 'INTRO', values: { kick: 1, bass: 0 } },
  { at: 8, len: 16, name: 'DROP', values: { kick: 1, bass: 1 } },
]
.gain(drums.kick.vol.mul(tlCurve('kick')))

9. Granular: striate / chop

s('quote').striate(24)   // split into 24 grains per cycle
s('quote').chop(16)      // cut into 16 slices in order
.begin(0.1).end(0.8)     // play only part of the sample
.speed(0.8)              // speed
.clip(0.4)               // shorter grain

striate is a "cloud" of shards, chop is sequential slicing. begin/end set a window in the sample (0…1); this is handy so you don't drag the whole quote.

10. Reverb, delay, jux

.room(0.6).roomsize(10)          // send and size
.delay(0.4).delaytime(0.375).delayfeedback(0.5)

delaytime is in cycles, not seconds: 0.375 = ⅜ of a bar (a triplet eighth), 0.25 = ¼.

jux(f) — a stereo trick: the original to the left, f(pattern) to the right. jux(rev) = the right channel plays the cycle backwards. juxBy(0.2, rev) — the same, but with a smaller width. Remember: this doubles the voices (and the load).

One reverb for several channels

room() is a send, not an insert. The reverb itself is created once per orbit (orbit 0 by default): all $: with .room() on that orbit send into the same reverbNode. So 18 channels of stack(...).room(...) are not 18 reverbs but one. 

// one reverb for the whole stack — economical
stack(kick, perc).room(0.6).roomsize(10)

// different roomsize on one orbit → the impulse response is recomputed
// different orbit → separate reverb/delay buses
stack(a.room(.2).orbit(1), b.room(.8).orbit(2))

What is expensive is not the number of .room() calls but the roomsize (impulse response length), changing roomsize on the fly (the reverb is recomputed) and separate orbits. Keep one roomsize per track; add an orbit only if you really need a different space or delay.

11. Kick: gaps, the "and" of 4, every/mask

The basic pattern:

s('bd').struct(m('x*4'))       // 4-on-floor

Gaps: either rebuild the bar or mute the layer:

// occasionally (12%) the bar turns into "~ ~ x ~"
s('bd').struct(m('x*4')).sometimesBy(0.12, (x) => x.struct(m('~ ~ x ~')))

// remove 10% of the hits without changing the grid
s('bd').struct(m('x*4')).degradeBy(0.1)

The "and" of the 4th beat is step 14 on the 16th grid. An extra hit every 4th bar: 

$: s('bd')
  .struct(m('~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ x ~'))
  .mask('<0 0 0 1>')   // 3 bars of silence, the 4th plays

every(4, fn) applies the function to every 4th cycle, but replaces the pattern on that bar; to "add", you need a separate layer with mask or stack.

12. LOOP / SONG / HOLD

The transport is declared in the UI manifest; the play slider has three states: 

const UI = {
  transport: { name: 'play', labels: ['loop', 'song', 'hold'] },
  holdBar: 'holdBar',
}

const play = slider(1, 0, 2, 1)      // 0 = LOOP, 1 = SONG, 2 = HOLD
const holdBar = slider(0, 0, 191, 1) // bar to snapshot for HOLD
const state = play.fmap((v) => Math.round(v))
const songGate = state.fmap((v) => (v === 1 ? 1 : 0))
const loopGate = state.fmap((v) => (v === 0 ? 1 : 0))
const holdGate = state.fmap((v) => (v === 2 ? 1 : 0))

// sectionValue(key) — the value from the TIMELINE section under holdBar
const tlOr = (key, loopLevel = pure(1)) =>
  tlCurve(key).mul(songGate).add(loopLevel.mul(loopGate))
    .add(sectionValue(key).mul(holdGate))

.gain(drums.kick.vol.mul(tlOr('kick')))        // LOOP — 1, SONG — timeline, HOLD — section under holdBar
.gain(vox.quote.vol.mul(tlOr('vox', pure(0)))) // off in LOOP

LOOP ignores TIMELINE and plays a constant mix; SONG follows the form; HOLD freezes the playhead and takes the section under holdBar.

13. Samples and why they "don't load"

if (typeof samples === 'function') {
  samples({ bd: ['bd/11_bd_mot4i.wav'] }, 'https://cdn.jsdelivr.net/gh/tidalcycles/uzu-drumkit@main/')
  samples({ quote: ['samples/de-quote/kafka.wav'] }, './')
}
  • raw.githubusercontent.com often returns 503 — some samples are silent. jsDelivr or local files are more reliable.
  • Check the console/Network: 404/503 is the sample, not the rhythm.
  • In node checks there is no samples() — hence the call under typeof.
