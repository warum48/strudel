# Подводные камни Strudel (наш опыт)

> **ВАЖНО. Правило №1 — любая mini-notation только через `m(...)`.**
> В реальном strudel.cc транспайлер оборачивает в `m()` **только двойные**
> кавычки. Одинарные остаются обычной строкой:
> `n('3 4 5')` → `"3 4 5" is not a number, falling back to 0`;
> `s('bd*4')` → бочки нет; `struct('x*4')` → нет сетки; `note('c4 e4')` → тишина.
> Наша панель перед eval вызывает `miniAllStrings()` и **маскирует** этот баг,
> поэтому трек может работать в панели и разваливаться в strudel.cc.
> Правило: ноты, `n`, `struct`, `s` с `*`/`<>`/`~`/`[]` — всегда `m('...')`.
> Обычные строки данных (UI-манифест, имена сэмплов) — в одинарных кавычках.
> `verify` ловит только строки в переменных, литералы внутри цепочки — нет.

Короткий список грабель, на которые мы уже наступали. Читать до того, как
писать трек. Каждый пункт — реальная поломка, а не теория.

## Мини-нотация и исходники

- **Строки мини-нотации — только через `m(...)`**: `note(m('d3 f3 a3'))`,
  `s(m('bd ~ sd ~'))`. В обычном strudel.cc `note('d3 f3')` может уйти в
  движок литеральной строкой — мелодия молчит, а барабаны при этом звучат.
- `m()` — это `mini.m`; в REPL он глобальный, в node-проверках приходит из
  `@strudel/mini`. Не переопределяй его.
- **Двойные кавычки = мини-нотация.** Транспайлер Strudel превращает любой
  строковый литерал, начинающийся с `"`, в `m("...")` (кроме аргументов
  `samples(...)`). Поэтому объект с двойными кавычками в коде ломает
  транспиляцию (`SyntaxError: Unexpected string`). Строки данных — только в
  одинарных кавычках (или в tagged template). UI-манифест — обычный JS-объект
  с одинарными кавычками и без кавычек в ключах: `{ switches: { gtr: ['riff','sparse'] } }`.
- `chord()` + `voicing()` живут в тональном пакете и есть в браузере, но
  **нет в `verify`** (там только core+mini). Если нужен зелёный `verify` —
  пиши явные ноты (`m('<[d3,f3,a3] ...>')`), а не символы аккордов.

## Длина событий и ритм

- `s('white').struct('<x ~ ~ ~ ~ ~ ~ ~>')` **не** даёт «один удар на 8
  тактов»: `struct` режет по сетке цикла и перетриггеривает каждый цикл —
  получается хэт. Для одного долгого события — `s('white').slow(8)`
  (один hap длиной 8 циклов) и уже на нём атака/сустейн/релиз.
- `seg(n)` — это **семплирование сигнала n раз за цикл**; на паттерне с
  нотами он множит число событий в n раз. `seg(8)` на аккорде из 3 нот =
  24 события за такт, и если на каждом висит `dist` — это 24 worklet-ноды.
- `slow(n)` растягивает событие, `fast(n)` ускоряет паттерн. Для «редко, но
  долго» — `slow`, для «чаще» — `fast`/`struct`.

## CPU: осцилляторы и worklet'ы

- `supersaw` — это **7 осцилляторов на голос**. `s('saw,supersaw')` × 3 ноты
  × `seg(8)` — уже сотни осцилляторов за такт, звук начинает рваться.
  Проверяй числом, а не на слух.
- `shape`, `crush`, `coarse`, `distort` и `ftype('ladder')` — **AudioWorklet
  на каждое событие**, движок их не переиспользует. На плотных партиях
  (16-е, `seg`) это гарантированные дропауты. Если очень нужен дисторшн —
  вешай его на редкие длинные события, а не на каждый шаг.
- `npm run cpu -- tracks/<...>.js` считает worklet'ы по факту. Бюджет:
  **до ~150/с** живёт спокойно; 300+ рвёт звук на слабых машинах.
- У `cpu` есть слепое пятно: он смотрит первые 8 тактов, поэтому слои,
  которые входят позже (VERSE 3 и т.п.), надо проверять отдельно — временно
  поднять их гейт в первой секции.
- «Тяжёлый инструмент» ≠ громкий. Сначала считай события и осцилляторы
  (`verify` печатает «ударов за такт»), потом крути громкость.

## Слайдеры и панель

- **Никаких отрицательных литералов в `slider(...)`**: виджет читает raw
  литерал, а `-2` — унарный минус → значение `NaN`, панель показывает
  `NaN`, дорожка немеет. Держи `0…N`, знак ставь в коде (`oct.mul(-12)`).
- **Один тембр — один слайдер.** Не привязывай другой инструмент к
  `vol` чужого инструмента: его не найти в пульте, и он живёт «в тени».
- Слайдер вне дерева `instruments` с `min 0` и `step 1` панель считает
  переключателем. Слайдеры внутри дерева — обычные ручки.
- Панель не должна знать имён трека, и метаданные не должны жить в
  комментариях (их стирают). Объявляй роли и варианты **в коде** —
  `const UI = { ... }` — обычный JS-объект (строки в одинарных кавычках):
  `transport: { name, labels }`, `holdBar: '...'`, `switches: { name: [...] }`.
  Панель разбирает литерал сама (без eval). Комментариев-маркеров больше нет;
  для старых треков без манифеста остаётся фолбэк на имена `song`/`holdBar`
  и легаси `@switches` (только ради подписей и правила ≥2 вариантов).
- **Выключенный слой не должен играть.** `gain(0)` всё равно строит
  осциллятор/сэмпл на каждое событие. Гаси на уровне паттерна:
  `.mask(tlOr(key).fmap(v => v > 0.001))` (у нас `gateOf(key)`), иначе в
  INTRO/OUTRO движок считает все выключенные барабаны и струнные зря.
  `node tools/levels.mjs <file> <bar>` теперь ругается на события с нулевой
  громкостью.
- **Один источник каждого шума.** Не держи два одинаковых `s('white')` для
  ризера и «воздуха»: brown/crackle/white — разные тембры, но проверяй, что
  белый шум не дублируется.
- **Уровни постоянны по секциям.** Не делай «в куплете тише, в припеве
  громче»: энергия — плотность, фильтр, decay. Перкуссия — исключение.
  Проверка баланса: `node tools/levels.mjs <file> <bar>`; лид не должен быть
  в 2 раза тише пэда.
- **Свитч рисуется только если есть из чего выбирать.** Число вариантов —
  длина массива в `UI.switches` (или подписей в легаси `@switches`): ≥2 —
  группа кнопок, одна — не свитч. Один ритм/вариант не выносим.
- Не каждый ритм обязан лежать в `grooves`: это только слоты, которые
  переключает `mode`. Один ритм остаётся в лейне как есть; разовые паттерны
  (rim, toms с `sometimesBy`) тоже не выносим. Нужен переключатель — это
  отдельный свитч (`autoSwitch`) и ключ в секциях, а не чужая группа.
- Панель повторяет структуру `instruments = { группа: { инструмент: {
  name, ...slider } } }`. Группа = первый уровень, инструмент = второй.
- `slider()` в обычном strudel.cc тоже работает (это сигнал), но наша панель
  транспилирует его в `sliderWithID` — не полагайся на это в музыкальной
  логике.

## Фильтры и автоматика

- `lpf` и `cutoff` — **один и тот же контрол**; если вызвать оба, победит
  последний. Не «складывай» ими срез.
- `lpenv` — глубина фильтр-огибающей **в октавах** (может быть < 0), а
  `lpa`/`lpd`/`lpr` — секунды. Это не LFO.
- LFO на срез, если нужен медленный: `sine.slow(n)` (n — тактов на цикл),
  а не `sine.fast`. Контролы сэмплируются на онсете события — на редких
  нотах получится ступенчатое движение, на 16-х — почти плавное.
- `AUTOMATION` должен быть **нативным**: `autoCurve` строит `arrange` из
  `pure`/`saw.range`. Панель только рисует точки. В обычном strudel.cc это
  должно звучать без панели.
- Префикс `autoCurve` до первой точки — `pure(1)`, иначе слой звучит глухо
  с самого начала.
- `tlCurve` **несёт последнее значение вперёд**: если новый ключ появился
  только в одной секции, во всех последующих он останется включённым, пока
  явно не поставить `0`.
- Свитчи, объявленные через `autoSwitch`, интерактивны **только в LOOP**.
  В SONG/HOLD их значение берёт TIMELINE, кнопки ничего не меняют — панель
  их прячет. Если нужен свитч, работающий всегда, не завязывай его на
  `autoSwitch`/секции.
- `AUTOMATION` — только для SONG. В LOOP она не должна менять звук:
  `autoAt = autoCurve*songGate + loopGate + снимок*holdGate` (в LOOP → ×1,
  в HOLD → значение на `holdBar`). Иначе в лупе трек «уплывает» по фильтрам.
- Разные `roomsize` у слоёв = пересборка impulse response и дропауты.
  Держи один общий `fx.reverb.size` и миксуй `room(...)`.
- `gain` до `stut()`/`echo()` бесполезен: они перезаписывают `gain`
  (`pow(feedback, i)`), первая копия идёт на 1.0 мимо ручки. Используй
  `echoWith`/`withValue` или ставь громкость после.
- Громкость после эффектов — это `postgain`, но `npm run gains` смотрит на
  `gain` и ругнётся «звучит при нуле». Если слой должен глушиться — ставь
  `gain` после `dist`/фильтра, а не только `postgain`.

## Сэмплы и шум

- `s('white')`, `s('pink')`, `s('brown')` — генераторы с зацикленным буфером;
  длинное событие тянется сколько нужно, но `brown` — это шум, а не тон.
  Если нужен «гул в тональности» — резонансный фильтр (`bpf`/`lpf` + `q`)
  на частоте ноты, а не просто шум.
- `hpf` выше фундаментала убивает тело: у низких нот либо опускай `hpf`,
  либо поднимай регистр.
- `struct('<x ~ ...>')` на сэмпле — тот же перетриггер по циклу; для «один
  раз за N тактов» нужен `slow(N)` и гейт по таймлайну.

## Проверки и структура файла

- `npm run verify -- tracks/...` — единственный источник правды о том, что
  паттерны парсятся и что реально попадает в сетку 1/16. Должен быть exit 0.
- `gains` ловит «звучит при нулевой громкости» (обычно `stut`/`echo`).
- `tension` (если есть маркер `// @roots ...`) — детектор случайной грязи,
  а не судья: осознанный диссонанс можно оставить.
- `verify` оборачивает каждый `$:`-блок в `P(...)`. Поэтому **строки
  продолжения блока должны начинаться с двух пробелов**, а закрывающие
  скобки вложенных `stack(...)` — тоже с отступом, иначе проверка упадёт
  на «missing )».
- Вспомогательные конструкции выноси в `const` перед блоком, а в `$:`
  оставляй одну строку (`$: stack(a, b, c)`) — так и проверка, и панель
  читают файл одинаково.
