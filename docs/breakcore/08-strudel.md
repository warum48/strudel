# 08 · Strudel: маппинг на этот репозиторий

Как перевести форумные техники в код, который здесь уже работает.
Проверено по `tracks/**/*.js`: используются `stack`, `slice`, `chop`, `ply`,
`degradeBy`, `sometimesBy`, `speed`, `crush`, `shape`, `lpf/hpf/lpq/ftype`,
`room/roomsize`, `delay/delaytime/delayfeedback`, `gain`, `pan`, `struct`, `euclid`.

---

## 1. Таблица соответствий

| Брейккор-техника | Strudel | Статус в репо |
|---|---|---|
| Нарезка на N слайсов | `s("amencutup").slice(16, "<0 2 3 5 ...>")` | ✅ используется |
| Гранулярный чоп по порядку | `.chop(8)` | ✅ используется |
| Ретриггер / ролл | `.ply(2)` / `.ply("<1 2 4>")` | ✅ используется |
| Note-off / обрезка хвоста | пауза `~` в паттерне + короткий amp-env | ✅ через паттерн |
| Вероятностная вариация | `.degradeBy(0.2)` | ✅ используется |
| «2 из 4» | `.sometimesBy(0.5, x => x.ply(2))` | ✅ используется |
| Реверс | `.sometimesBy(0.18, x => x.speed(-1))` | ✅ (`dnb/02`) |
| Пере-питч слайса | `.speed("<1 1.12 0.89>")` | ✅ используется |
| Бит-круш | `.crush(4)` | ✅ используется |
| Дисторшн/шейпинг | `.shape(0.4)` | ✅ используется |
| Убрать низ брейка | `.hpf(150)` | ✅ используется |
| Глухой кик | `.lpf(80)` | ✅ (правило репо) |
| Комб/резонанс | `.lpq(2)` + `ftype("24db")` | ✅ используется |
| Делэй-глитч | `.delay(0.2).delaytime("<0.125 0.0625>").delayfeedback(0.4)` | ✅ используется |
| Реверб-пространство | `.room(0.1).roomsize(4)` | ✅ используется |
| Полиритмия | `struct("x ~ ~ x ~ ~")` / `euclid(3,8)` | ✅ используется |
| Стек слоёв | `stack(...)` | ✅ используется |
| Offset-триггер (`09xx`) | `.begin("<0 0.25 0.5>")` | ⚠️ проверить `npm run verify` |
| Choke-группы (note-off) | `.cut(1)` | ⚠️ проверить `npm run verify` |

Если функция не проходит `npm run verify` — не использовать, заменить паттерном.

## 2. Скелет трека под этот репо

Стиль файлов: `tracks/<genre>/NN-name.js`, шапка-комментарий на русском с
источниками, константы вверху, `mode`-переключатель, `stack(...)` в конце.

```js
// ══════════════════════════════════════════════════════════════════
//  BREAKCORE 01  ·  Strudel  ·  174 BPM  ·  rinse / note-off
//
//  ── ЧТО ПРОЧИТАНО ВОВНЕ ───────────────────────────────────────
//  • rinse technique: note-off перед каждым сэмплом, одна колонка,
//    один DSP на весь брейк [renoise #29927 #1].
//  • резать по 1/4–1/8, не по 16-м; 3–5 маркеров достаточно
//    [elektronauts #226901, #175570].
//  • не варпить чопы: «Warp is the groove killer» [#175570].
//  • разрежение: ≤3 элемента, одна 16-я за раз [#173927].
//
//  ── СЭМПЛЫ ────────────────────────────────────────────────────
//    amencutup — 32 нарезанных Amen (Dirt-Samples)
//    amen      — полный брейк (clean-breaks)
//    hardcore  — кик/снейр для акцентов
// ══════════════════════════════════════════════════════════════════

samples('github:tidalcycles/Dirt-Samples')
samples('github:yaxu/clean-breaks/main')

const mode = 0   // 0 rinse · 1 stems · 2 solo

// 1) основной брейк: крупная нарезка, паузы вместо хвостов
const breakRinse = s("amencutup")
  .slice(8, "<0 0 2 3 0 4 5 6> <1 1 3 4 1 5 6 7>")
  .hpf(150).lpf(9000)
  .crush(3).shape(0.3)
  .gain(0.8).room(0.08).roomsize(3)

// 2) кик: глухой по правилу репо
const kick = s("hardcore:4")
  .struct("x ~ ~ ~ x ~ ~ ~ x ~ ~ ~ x ~ ~ ~")
  .lpf(80).shape(0.4).gain(0.9)

// 3) снейр: 3 варианта + ghost
const snare = s("<hardcore:10 hardcore:11 hardcore:10>")
  .struct("~ ~ ~ ~ x ~ ~ ~ ~ ~ ~ ~ x ~ ~ ~")
  .gain("<0.9 0.7 0.8 0.4>")   // последний — ghost
  .hpf(200).room(0.12).roomsize(2)

// 4) саб: моно, под кик
const sub = note("a1").s("sine")
  .struct("x ~ ~ ~ ~ ~ x ~")
  .lpf(80).gain(0.5)

stack(kick, snare, breakRinse, sub)
```

Это скелет, не готовый трек: дальше — 4-тактовая мутация, снейр-раш, участок
«соло» без кика.

## 3. Рецепты в коде

### R1 · Rinse
```js
s("amen").slice(8, "<0 1 2 3 4 5 6 7>")
  .hpf(150).lpf(10000).crush(3).shape(0.35)
  .gain(0.8)
// паузы вместо хвостов: `~` в паттерне слайсов
```
Соответствует `[29927#1]`: одна колонка, одинаковый DSP, обрезка.

### R2 · Снейр-раш (роллы)
```js
s("<hardcore:10 hardcore:10 hardcore:11>")
  .struct("~ ~ ~ ~ x x x x ~ ~ ~ ~ x x x x")
  .ply("<1 2 3 4>")
  .speed("<1 1.06 0.94>")
  .gain("<0.9 0.7 0.8 0.5>")
```
Ролл + пере-питч + velocity — три отдельные ручки `[18985#65, #66]`.

### R3 · Генеративная вариация (дозированно)
```js
s("amencutup").slice(8, "<0 1 2 3 4 5 6 7>")
  .degradeBy(0.15)
  .sometimesBy(0.5, x => x.ply(2))
  .sometimesBy(0.18, x => x.speed(-1))
```
Это «2 из 4» и chance-филлы, а не рандомайзер `[173927]`.

### R4 · Полиритмия без боли
```js
stack(
  s("hardcore:4").struct("x ~ ~ x ~ ~").lpf(80),      // 3
  s("hardcore:10").struct("~ ~ ~ x ~ ~ ~ ~ x").hpf(200) // 5
)
```
Кик каждые 3, снейр каждые 5 → разрешение через 15 долей `[173927]`.

### R5 · Нечётный метр
```js
s("amencutup").slice(8, "<0 1 2 3 4 5 6 7>")
  .struct("x ~ ~ x ~ ~ x ~ ~ x ~ ~ x ~ ~ x ~ ~ x ~")   // 20 шагов = 5/4
```
20 строк @ LPB 4 = 5/4 — та же арифметика, что в трекере `[2328#7]`.

### R6 · Делэй-глитч вместо плагина
```js
s("amencutup").slice(4, "0 1 2 3")
  .delay(0.25)
  .delaytime("<0.125 0.0625 0.25>")
  .delayfeedback(0.45)
  .room(0.1)
```
Короткий делэй с высоким feedback и меняющимся временем — «chorus glitch»
без плагинов `[18985#37]`.

## 4. Ограничения этого репозитория (`docs/rules.md`)

Обязательно к соблюдению — это важнее форумных советов:

- Бас по умолчанию `lpf(80)`, не выше.
- Кик максимально глухой (`lpf(80)`), без «щелчка».
- Никаких смешных мелодических линий; 303 — только для атональных рифов и
  арпеджио с малым числом нот, не для обыгрывания аккордов.
- Избегать банальных 4-тактовых `1–2–4–5`; больше висячих нот и контрапункта.
- Не имитировать саксофон/регги без запроса.
- Музыка должна быть «ультрастильной», не «смешной» и не в заигранном центре.

Для брейккора это значит: **барабаны — главное, гармония — фон**. Если хочется
«красивую» мелодию, лучше сделать её минимальной и оставить место барабанам.

## 5. Проверка перед коммитом

```bash
npm run verify     # движок реально исполняет паттерн
npm run modes      # переключение mode-веток
npm run tension    # нет ли статики/провисаний
npm run gains      # нет ли клиппинга по громкости
npm run doubles    # нет ли дублирующихся слоёв
npm run cpu        # не слишком ли тяжёлый паттерн
```

Плюс чеклист из `README.md` §7 и диагностика из `07-pitfalls.md`.
