# strudel tracks

Треки для [strudel.cc](https://strudel.cc) + чекер, который прогоняет их через
настоящий движок Strudel в node — без браузера, без звука, без установки заново
каждый раз.

## Как играть

1. Открой https://strudel.cc
2. Вставь содержимое файла из `tracks/` в редактор
3. `Ctrl+Enter`

Слайдеры — это виджеты прямо в коде: тянешь мышкой, звук меняется сразу,
перезапускать ничего не нужно. Кнопок в Strudel нет, поэтому переключатели
сделаны слайдерами с шагом 1 (см. `mode` в v2).

> **Перед драгом слайдера жми `Ctrl+Enter`.** Ползунок в strudel.cc откатывается
> к значению с последнего запуска после любого скролла, и драг по такому
> ползунку портит число в коде (`0.8.55` → `SyntaxError`). Звук при этом
> правильный. Подробно — `docs/slider-bug.md`.

## Структура

```
tracks/
  01-dnb-live.js      174 BPM drum & bass, 22 слайдера
  02-dnb-live-v2.js   + переключатель ритма, мелодия, злой саб
  03-dnb-live-v3.js   + дрон на такт с качающимся фильтром (38 слайдеров)
  04-dnb-live-v4.js   + бас-линия Bb→C→F с фильтром от нажатия (44 слайдера)
  techno/
    01-berlin.js      130 BPM берлинское техно, без аккордов (43 слайдера)
    02-dub.js         124 BPM техно-даб: пэд, реверб, бульки, глитчи (62 слайдера)
    03-dub-v2.js      + режимы ударных, микшер наверх, атонал⇄джаз (64 слайдера)
    04-dub-v3.js      + широкие слайдеры 180px, звук как в 03 (64 слайдера)
    05-deep-dub.js    112 BPM, 26 дорожек: глубже, одна тональность на два режима
docs/
  references.md       форумы, доки, код людей + разбор LFO фильтра по исходникам
  slider-bug.md       почему ползунок откатывается и портит код (баг strudel.cc)
  issue-slider-bug.md готовый текст отчёта в апстрим (Codeberg требует аккаунт)
tools/
  verify.mjs          прогон трека через движок, сетка 1/16 + статические линты
  doubles.mjs         разбор «что играется дважды»: такт 0 против такта 1
  tension.mjs         тритоны и малые секунды: фразы против корней и пэдов
  live.mjs            живая проверка в настоящем strudel.cc (headless Chromium)
  patch-strudel.mjs   postinstall-заплатка, чтобы @strudel/core грузился в node
```

Две независимые серии: **drum & bass** (`tracks/01…04`) и **techno**
(`tracks/techno/01…`). Внутри серии треки — версии одного трека, а не разные:
02 = 01 + новое, 03 = 02 + новое. Старые не трогаем, чтобы было видно, откуда
что выросло. Новая серия = новая подпапка, `npm run verify` обходит их рекурсивно.

Исключение из «версий»: `techno/02-dub.js` — не версия Берлина, а **другой
трек** (другая гармония, другой грув, другой набор дорожек). Версии — это когда
меняется характер одного трека; новый трек — это новый трек. `03-dub-v2.js` —
версия именно дуба: 02 + режимы ударных + микшер + переключатель гармонии.
`04-dub-v3.js` — тоже версия дуба, но правка не музыкальная: ширина слайдеров
(64 → 180px), звук байт в байт как в 03.

`05-deep-dub.js` — уже **другой трек**, не версия: медленнее (112), вдвое больше
инструментов (26), другая гармоническая логика. Главное отличие: раньше атонал и
джаз были разными мирами, и общая мелодия между ними не жила. В 05 оба режима
сидят в одной тональности (C эолийский) и различаются только укладкой — кварты
без терций против аккордов с 9-ми. Поэтому переключение никогда не даёт грязной
ноты, а часть дорожек (орган, общая мелодия, арпеджио, бас) играет в обоих
режимах и не дёргается. Это правило стоит переиспользовать: **два режима — одна
тональность, разная укладка.**

Ещё одно правило из 05: **у ручки максимум должен быть максимумом.** Слайдер
`clapCrush` был устроен так, что «хорошо» (тонкие щелчки) жило в его МИНИМУМЕ, —
ручка работала против себя. Теперь `percThin`: 0 — мясо, 1 — иголка, и от него
считаются три параметра сразу (биткраш, срез снизу, длина огибающей), потому что
тонкость — это не одна ручка, а связка. Производные сигналы
(`percThin.mul(-15).add(16)`) — обычные паттерны, их можно класть в любой контрол.

### Правило версий (жёсткое)

**Любая новая музыкальная идея — новый файл.** Хочешь другой бас, другой старт,
другие дефолты, другой характер бочки — это `05-…` / `02-berlin.js`, а не правка
предыдущего. Прошлый файл остаётся ровно таким, каким его слушали.

Править старый файл можно **только** когда он не работает: молчит дорожка,
слайдер откатывается, движок падает. Это не версия трека, это поломка —
сохранять её незачем.

## Проверка

```bash
npm install          # один раз
npm run verify                    # все треки
npm run verify -- tracks/02-dnb-live-v2.js
npm run doubles -- tracks/techno/01-berlin.js   # разбор наложений
npm run tension -- tracks/techno/05-deep-dub.js # тритоны и малые секунды
npm run live                      # живой strudel.cc: грузится ли файл и играет ли
npm run live -- tracks/techno/02-dub.js
```

Печатает, что реально попадает в сетку: номер доли, имя сэмпла или ноты.
Ловит опечатки в мини-нотации, несуществующие функции, пустые дорожки.
Плюс статические проверки, которые движок в node не заметит, а браузер — да:
строки мини-нотации в переменных без `m()`, `slider()` с не-числовым первым
аргументом, слайдеры, которые объявлены и нигде не читаются. Ещё одна строка —
`⚠ один сэмпл в одной позиции от разных дорожек`: это карта наложений, то,
что слышно как удар дважды.
Не ловит, как это звучит — для этого нужны уши.

**`npm run live` — это другой вопрос.** `verify` гоняет движок в node; он ничего не
знает про редактор. `live` открывает настоящий https://strudel.cc в headless
Chromium, вставляет файл, жмёт eval и печатает: есть ли паттерн, сколько слайдеров
в конфиге и сколько отрендерено, и не врёт ли ползунок после скролла. Нужен
локальный Chromium (или `CHROME=/path/to/chrome npm run live`). Пример вывода:

```
== tracks/techno/03-dub-v2.js (16946 символов) ==
  eval:        ок
  паттерн:     играет
  слайдеров:   64 в конфиге, 6 отрендерено (остальные за вьюпортом)
  слайдер:     драг 0 → 0.55; в коде "0.55", ползунок "0" ← РАССИНХРОН
```

`РАССИНХРОН` — это баг strudel.cc, а не трека (см. ниже и `docs/slider-bug.md`).

### `npm run tension` — где именно «шипит»

Слухом тритон ищется плохо: он может быть между мелодией и одной нотой пэда
в другой октаве, и на общем миксе это слышно как раздражение, а не как интервал.
Скрипт читает фразы из файла трека и считает интервалы:

- нота против **корня такта** — тритон (6 полутонов) в любой октаве;
- нота против **нот пэда этого такта** — тритон и малая секунда (1 полутон),
  но только в одной октаве: секунда через октаву уже краска, а не грязь.

Что нужно от трека: строка-маркер `// @roots c ab f bb eb g f ab` и пэды
`PAD_A` / `PAD_B`. Режим определяется суффиксом имени: `MEL_A`/`STAB_A`
сравниваются только с `PAD_A`, `MEL_B`/`STAB_B` — только с `PAD_B`,
всё остальное (общие партии) — с обоими. Это важно: сравнивать партию
с пэдом, который в этот момент не звучит, — значит находить несуществующие
конфликты.

Проверяется столько тактов, чтобы все фразы прошли полный дрейф против
гармонии (в 05 это 240). Малая нона НЕ флагуется: в Cm9 живут и b3, и 9.

## Грабли движка (проверено на 1.2.6)

- **`slider()` — только виджет редактора.** Он возвращает непрерывный сигнал,
  поэтому живыми могут быть только параметры паттерна (`gain`, `lpf`,
  вероятности). `setcpm(slider(...))` живым НЕ будет — темп читается один раз
  при запуске. Темп меняется правкой числа + `Ctrl+Enter`.
- **`"1 2".mul(150)` из документации не работает** — `String.prototype.mul`
  не существует. Правильно наоборот: `hatVol.mul("[1 .35 .6 .35]*4")`.
- **`degradeBy` / `sometimesBy` съедают событие в нулевой позиции — при ЛЮБОМ
  аргументе, не только 0.** `rand` в `t=0` равен 0, а условие «оставить» —
  `rand >= x`, то есть первый удар выбрасывается всегда. Поэтому бочка в 01
  разбита на две дорожки, а не глушится вероятностью, и поэтому у дорожки
  `клики` в `02-dub` первый такт может быть пустым — это не поломка.
- **🛑 `every(n, f)` срабатывает на НУЛЕВОМ такте.** `every(4, x => x.ply(2))`
  на хэтах означает: первый же такт, который ты слышишь после `Ctrl+Enter`,
  уже идёт дробью — в 01-berlin это давало 74 события в такте 0 против 40 в
  такте 1 (32-е вместо 16-х), и это слышно как «играет дважды». Если дробь
  нужна на 4-м такте, а не на первом — `lastOf(4, x => x.ply(2))`
  (срабатывает на 3-м, 7-м, 11-м). В `02-dub` так и сделано.
- **Защёлка переключения на границе фразы — `seg`.** `harmony.seg(1/8)` даёт
  сигнал, который сэмплируется один раз в 8 тактов: двинул слайдер — значение
  подхватится только на следующей границе, начатая фраза доиграется. Проверено:
  слайдер двинут на 3.5-м такте → переключение на 8-м (такты 0–7 старый режим,
  8+ новый). Плюс `gain` читается в момент удара, поэтому уже звучащий аккорд
  доигрывает в любом случае. Так сделан переключатель атонал ⇄ джаз в
  `03-dub-v2`: два пэда и два стаба, у каждого свой гейт `hAtonal` / `hJazz`.
- **Дубли ловятся не на слух, а сеткой.** `npm run doubles -- <файл>` печатает
  по каждой дорожке события такта 0 и такта 1: если в такте 0 их больше —
  что-то стреляет только на старте. Плюс карту «позиция:сэмпл → дорожки»:
  один сэмпл в одной позиции от двух разных дорожек = удар дважды. Именно так
  нашлось, что в `01-berlin` бочка и румбл — обе `s("bd")` в 0, 4, 8, 12.
  Вариант сэмпла учитывается: `hh` и `hh:2` — разные звуки, не дубль.
- **`penv` / `panchor` (питч-огибающая) в опубл. `@strudel/core` нет**, хотя в
  доках пример с ними есть. Не используем — злой саб сделан падением `f2 → f1`.
- **Контрол сэмплируется в момент удара.** Поэтому `.lpf("<200 900>")` на одной
  длинной ноте даст один скачок за такт, а не плавный свип. Чтобы фильтр двигался
  *внутри* ноты, нужен LFO: `lpdepth` + `lpsync`. Подробнее — `docs/references.md`.
- **Длину ноты задаёт вес `@`.** `note("bb1 c2 f1@1.5 ~@0.5").slow(4)` — такт,
  такт, полтора такта ноты и полтакта паузы. Проверяется `queryArc`: `0+1 1+1 2+1.5`.
- **`release` — единственный способ дотянуть ноту.** Отпускание всегда идёт *после*
  конца события, поэтому «последние полтакта тает» = событие короче на полтакта
  плюс `release` на полтакта. `lpr` (фильтр) закрывается синхронно с ним.
- **Огибающая фильтра — в секундах, не в долях.** `lpa` / `lpd` / `lpr` — секунды,
  `lpsustain` — 0..1. Полтакта на 174 BPM = 0.69 с; в v4 это считается от темпа
  (`barSec / 2`), чтобы не разъезжалось при смене BPM.
- **🛑 Строка мини-нотации в переменной НЕ парсится.** Транспайлер REPL оборачивает
  в `m()` только строковые литералы; строку, лежащую в переменной, он не видит.
  `const BASS = "c2 ~ c2 ~"` + `note(BASS)` = одна «нота» из всего текста, то есть
  тишина. Лечится явным `m()`: `const BASS = m("c2 ~ c2 ~")`. `npm run verify`
  статически ловит такие переменные, печатает `✗ строки в переменных без m()`
  и падает с ненулевым кодом.
- **🛑 `slider()` принимает только числовой литерал.** ID слайдера —
  `slider_<смещение первого аргумента>`, а значение виджета берётся из
  `node.arguments[0].raw`. У выражения (`slider(halfBar, …)`) `raw` нет → значение
  `undefined`, перетаскивание падает на `originalValue.length`, а при следующем
  запуске слайдер откатывается к тому, что написано в коде. Только числа.
  `npm run verify` ловит такое (`✗ первый аргумент не число`) и падает.
- **Значения слайдеров живут в тексте кода.** `sliderWithID` при каждом запуске
  делает `sliderValues[id] = <значение из кода>`, а перетаскивание переписывает
  число прямо в тексте. Поэтому «слайдер не слушается» лечится `Ctrl+Enter`:
  состояние пересоберётся из кода.
- **🛑 Ползунок откатывается после скролла и может испортить код — это баг
  strudel.cc, не наш.** `toDOM()` ставит ползунок на значение, застывшее с
  последнего `Ctrl+Enter` (`this.value`), а `eq()` возвращает `false`, поэтому
  DOM-узел пересоздаётся при каждом пере-рендере. Дальше драг считает длину
  заменяемого числа от старого значения: `0.55` + драг → `0.8.55` → `SyntaxError`.
  Звук при этом правильный (живое значение в `sliderValues`), врёт только
  ползунок. Правило: **перед драгом — `Ctrl+Enter`; выглядит сброшенным — не
  тяни, сначала `Ctrl+Enter`; не скроллить во время игры.** Разбор с выводом
  теста — `docs/slider-bug.md`.
- **Ширина слайдера — 64px инлайном, перебивается `!important`.** В `toDOM()`
  стоит `style="width:64px"` без `!important`, поэтому `.cm-slider input
  { width: 180px !important }` работает (замерено: 160 и 180 — вёрстка не едет,
  320 — строки лезут вправо). Ставить либо строкой в файле трека (`document`
  в eval доступен), либо снаружи через Stylus. Точные значения удобнее не мышкой,
  а `←`/`→` на сфокусированном слайдере: ровно один шаг и не попадает в баг
  с длиной числа. Детали — `docs/slider-bug.md`.
- **Рандом на ноту — это `rand`.** Он непрерывный, но контрол читается один раз на
  удар, поэтому `lpenv(rand.range(2.4, 3.6))` даёт своё значение каждой ноте.
  В v4 поверх слайдера: `jit(amt)` = множитель `1 ± amt`, так что живой контроль
  остаётся, а повторы фразы не одинаковые.
- **`<a b c …>` с N элементами = N тактов.** Так пишутся длинные фразы. Переносы
  строк внутри мини-нотации — просто пробелы, поэтому фразу можно расписать по
  строке на такт: в `techno/01` это делает хелпер `phrase([...])` = `<` + join + `>`.
- **`fm()` есть, но значение лежит в поле `fmi`.** Так в доках и написано: `fm` —
  синоним `fmi`. `.fm(2)` работает (FM-колокольчик в `techno/01`), просто не ищи
  `fm` в `hap.value`. `fmh` — гармоничность: нецелая (2.41) даёт металл, целая —
  певучесть. `fmdecay`/`fmsustain` — огибающая индекса: удар яркий, хвост тусклый.
- **`transpose` в 1.2.6 нет.** Транспонировать — через `.add(note("12"))`;
  `.add(12)` на нотном паттерне падает с `Can't do arithmetic on control pattern`.
- **`.every(n, f)`** срабатывает на каждом n-м такте (проверено: `every(3)` → такты
  0, 3, 6). Так делается «лом» без расписанной аранжировки.
- **Гасить слои лучше гейном, а не `mask`.** `.gain(vol.mul(modeOn(k)))` с
  `modeOn = mode.fmap(m => m === k ? 1 : 0)` работает железно и переключается на
  лету — так сделаны три режима барабанов в `techno/01`.

## Палитра эффектов (что реально есть в 1.2.6)

Проверено перебором экспортов `@strudel/core`, чтобы не изобретать имена:

- `crush(1…16)` — биткраш, 1 = злой, 16 = почти чисто. `coarse(2…)` — грубее,
  но работает только в хромиум-браузерах.
- `stut(times, feedback, time)` — стутер: `stut(4, 0.55, 0.03125)` = 4 повтора
  на 1/32. `echo` — то же, но без затухания по гейну.
- `vowel("<a e o u>")` — формантный фильтр, аккорд начинает «говорить».
  `chorus(0…1)` — ширина. `jux(f)` — две копии влево/вправо. `chop(n)` /
  `striate(n)` — резать сэмпл.
- `lastOf(n, f)` / `firstOf(n, f)` — применить к последнему/первому из n тактов.
  `when(cond, f)` — по условию от номера такта. `struct("x ~ x ~")` — ритм-маска.
- `sometimesBy(p, f)`, `sometimes` / `often` / `rarely` / `almostAlways` /
  `never`, `degradeBy(x)` — рандом. `brand`, `perlin`, `irand`, `wchoose`,
  `choose` — рандом-сигналы и выбор из списка.

## Если git не может записать index

В этой папке (`~/Local Docs`) git умеет **создавать** lock-файлы, но не может их
**удалить**: `unable to unlink '.git/index.lock': Operation not permitted`. Сам `rm`
из шелла тот же файл удаляет без проблем, то есть это не права, а то, как git
делает unlink.

Отсюда два следствия, оба выглядели как «в репозитории уже крутится другой git»:

- `git status` тоже пишет `.git/index.lock` (обновляет stat-инфо) и оставляет его
  после себя → следующая команда падает с `File exists`;
- `git commit` оставляет `.git/HEAD.lock` и `.git/refs/heads/master.lock`, после
  чего репозиторий «залочен» навсегда, хотя никакого процесса нет.

Лечится так:

```bash
# 1. чтение — без lock-ов вообще
GIT_OPTIONAL_LOCKS=0 git status
GIT_OPTIONAL_LOCKS=0 git log --oneline

# 2. запись — индекс в /tmp + сначала убрать все протухшие lock-и
find .git -name "*.lock" -delete
cp .git/index /tmp/idx
GIT_INDEX_FILE=/tmp/idx git add -A
GIT_INDEX_FILE=/tmp/idx git commit -F msg.txt
cp /tmp/idx .git/index          # вернуть индекс на место
```

`cp` перезаписывает файл по содержимому, без unlink/rename — поэтому проходит.
Признак, что дело именно в этом: в ошибке `File exists`, а `ls .git/*.lock`
показывает файл, которого «не должно быть».

## Почему `patch-strudel.mjs`

Опубликованный `@strudel/core` тянет `@kabelsalat/web` (браузерный REPL) и падает
в node на импорте. Патч подменяет его заглушкой; запускается автоматически
из `postinstall`. Если `npm install` делали с `--ignore-scripts` — запусти
`node tools/patch-strudel.mjs` руками.

## Добавить трек

Копируешь любой файл из `tracks/`, меняешь `$:`-дорожки, гоняешь `npm run verify`.
Каждый `$:`-блок — отдельная дорожка; комментарий над ним печатается как имя.
