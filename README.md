# strudel tracks

Треки для [strudel.cc](https://strudel.cc) + чекер, который прогоняет их через
настоящий движок Strudel в node — без браузера, без звука, без установки заново
каждый раз.

## Перед новым треком

Сначала `docs/switchangel-recipes.md` — там чужие рецепты (слайд, 303, бас,
фильтры, грув). Половина ручек, которые мы пишем руками, уже сделана одной
функцией и сделана лучше.

## Как играть

1. Открой https://strudel.cc
2. Вставь содержимое файла из `tracks/` в редактор
3. `Ctrl+Enter`

Слайдеры — это виджеты прямо в коде: тянешь мышкой, звук меняется сразу,
перезапускать ничего не нужно. Кнопок в Strudel нет, поэтому переключатели
сделаны слайдерами с шагом 1 (см. `mode` в v2).

> **Ползунок в strudel.cc откатывается к значению с последнего запуска после
> любого скролла, и драг по такому ползунку портит число в коде** (`0.82` +
> ползунок `0.5` → `0.62`, при другом раскладе `0.8.55` → `SyntaxError`).
> Звук при этом правильный. В `06-deep-dub-v2.js`, `07-dark.js` и `08-dark-acid.js`
> это вылечено заплаткой прямо в треке (блок «СИНХРОНИЗАЦИЯ ПОЛЗУНКОВ»),
> в остальных файлах — пока только правило: перед драгом жми `Ctrl+Enter`.
> Подробно — `docs/slider-bug.md`.

Три независимые серии: **drum & bass** (`tracks/01…04`), **techno**
(`tracks/techno/01…`) и **atmospheric dnb** (`tracks/dnb/01…`). Внутри серии
треки — версии одного трека, а не разные:
02 = 01 + новое, 03 = 02 + новое. Старые не трогаем, чтобы было видно, откуда
что выросло. Новая серия = новая подпапка, `npm run verify` обходит их рекурсивно.

Исключение из «версий»: `techno/02-dub.js` — не версия Берлина, а **другой
трек** (другая гармония, другой грув, другой набор дорожек). Версии — это когда
меняется характер одного трека; новый трек — это новый трек. `03-dub-v2.js` —
версия именно дуба: 02 + режимы ударных + микшер + переключатель гармонии.
`04-dub-v3.js` — тоже версия дуба, но правка не музыкальная: ширина слайдеров
(64 → 180px), звук байт в байт как в 03.

`05-deep-dub.js` — уже **другой трек**, не версия: медленнее (112), вдвое больше
инструментов (26), другая гармоническая логика. Главное отличие: раньше атонал и
джаз были разными мирами, и общая мелодия между ними не жила. В 05 оба режима
сидят в одной тональности (C эолийский) и различаются только укладкой — кварты
без терций против аккордов с 9-ми. Поэтому переключение никогда не даёт грязной
ноты, а часть дорожек (орган, общая мелодия, арпеджио, бас) играет в обоих
режимах и не дёргается. Это правило стоит переиспользовать: **два режима — одна
тональность, разная укладка.**

Ещё одно правило из 05: **у ручки максимум должен быть максимумом.** Слайдер
`clapCrush` был устроен так, что «хорошо» (тонкие щелчки) жило в его МИНИМУМЕ, —
ручка работала против себя. Теперь `percThin`: 0 — мясо, 1 — иголка, и от него
считаются три параметра сразу (биткраш, срез снизу, длина огибающей), потому что
тонкость — это не одна ручка, а связка. Производные сигналы
(`percThin.mul(-15).add(16)`) — обычные паттерны, их можно класть в любой контрол.

`06-deep-dub-v2.js` — версия 05, и музыка в ней **байт в байт как в 05**: те же
корни, те же фразы, та же гармония, те же дефолты (звучит только атмосфера).
Изменены только ударные:

- **четвёртый режим** `mode = 3` — брейк: бочка на 1, на 3 и на «а» третьей,
  снейр-бэкбит на 3, два призрака, 16-е хэты с акцентами, филл 32-ми по снейру
  раз в 4 такта;
- **режим 2 изменён**: бочка не четыре в пол, а на каждый второй бит (2 и 4) —
  отсюда другой грув, пусто на 1 и 3;
- две новые ручки: `sdVol` и `sdCut` (снейр). Больше ничего не добавлено.

Гейт «четыре в пол» пришлось вынести в отдельный сигнал `m01 = mode <= 1`:
бочка — единственная дорожка, где три разных рисунка лежат в одном `stack`,
и общий `.gain(kickVol)` снаружи стёр бы гейты режимов (`gain` СТАВИТ
громкость, а не умножает). Поэтому громкость умножается внутри каждой ветки.

Ещё в 06 появилась **заплатка на баг слайдеров** (блок «СИНХРОНИЗАЦИЯ
ПОЛЗУНКОВ»). Виджет запоминает число на момент `Ctrl+Enter` и после скролла
строит ползунок из него, хотя в коде уже стоит накрученное; драг по такому
ползунку заменяет не ту длину и портит число. Заплатка перед каждым нажатием
и на каждый скролл подтягивает `el.originalValue` / `el.value` к тексту в коде.
В документ не пишет, звук не трогает — чинит ровно две вещи, которые врут.
Замер: `05` без неё — ползунок `0` против кода `2`; `06` с ней — `3` против `3`.

`07-dark.js` — снова **другой трек**, не версия: 126 BPM, дарк-техно. Правило
«одна тональность, две укладки» осталось, но тональность другая по смыслу:
**C фригийский**, где главная нота — `b2` (`db`). Она делает музыку тревожной,
а не печальной: минор — это грусть, `b2` — это угроза. `b2` живёт в трёх
местах сразу: в пэде первого такта (`db4` против `c3`), в мелодии как `b9`
и в басу как ход `c2 → db2 → c2` (I–bII–I, самый узнаваемый жест лада).

Второе отличие — **намеренный диссонанс**. Два тритона, оба в первом такте:
стаб играет `gb` над `c` (четверть, раз в 8 тактов), орган держит `g3` против
`db4` пэда (это C7b9 без терции, целый такт). Всё остальное — чисто, потому
что у фраз длиной 7, 5 и 12 тактов тритон всплывал бы в случайном месте.
Механика — маркер `// @dark`, см. раздел про `tension` выше.

`08-dark-acid.js` — **другой трек**, 180 BPM: хард-эйсид на стыке с габбером.
Правило «одна тональность, две укладки» осталось, но гармония здесь стоит:
корни `a a bb bb` — не прогрессия, а сдвиг на полутон и обратно (i–bII–i),
и движение даёт не аккорд, а **303-линия**. Мелодии в файле нет вообще —
впервые за серию, её роль играет линия.

**Регистры разведены жёстко** (это выяснилось на правке, см. грабли про
полосы): бас `a1…f2` = 55–87 Гц, 303 `a2…c4` = 110–260, пэд `a3…g4` = 220–390,
стаб до `c5`. Первая версия держала линию в `a3…c5` — это не эйсид, а свисток,
и одновременно она пыталась быть басом. Теперь низ держит отдельная дорожка
`BASS` (две расстроенные пилы, срез 200 Гц, `orbit 2` — её дакает бочка),
а линия освобождена от обязанности быть низом.

Что нового по механике:
- **Бочка — параметр высоты.** `speed(kickTune)` (0.75 по умолчанию) опускает
  сэмпл `bd` до габбера и удлиняет его; `shape` добивает верх. Пять режимов
  ударов вместо четырёх: топот / габбер / лом / брейк / **ролл** (16-е бочки,
  12 ударов в секунду — под него своя дорожка с коротким `decay`).
- **303 из трёх частей**: фильтр-огибающая (`lpenv` + `lpa(2мс)` + короткий
  `lpd`), акценты (gain-паттерн на 16 шагов) и подъезды (`penv` + `panchor(1)`,
  см. грабли про `penv`). Слайдеры `acidSlide` (глубина) и `acidSlideTime`
  (длина) — это и есть «ручка 303».
- **Четыре разных вида грязи на своих местах**: `shape` — бочка и эйсид-крик,
  `distort` — хувер, `crush` — клэп и эйсид-крик, `drive` — подгруз самого
  ladder-фильтра 303. Не «дисторшн везде», а четыре инструмента. Где какой
  можно ставить, решает не вкус, а CPU: worklet на каждое событие, см. грабли
  про worklet'ы выше — поэтому на хэтах (58 событий в такт) нет ни одного.
- **Хувер** — рейв-аккорд 90-х: суперпила, питч-огибающая вниз на октаву,
  вокальный фильтр, большой реверб.

Проверки: 23 дорожки / 183 удара / 79 слайдеров, `tension` — трения нет
(31 намеренный тритон, все в якорных фразах: `eb` над `a` — это и есть эйсид),
`modes` — все пять режимов дают свой рисунок, `latch` — пэды меняются на 8-м
такте, `gains` — глушится в ноль, `live` — eval ок, 180px, ползунок = код.

`09-dark-acid-v2.js` — **версия 08**, правка не музыкальная, а техника слайда.
В 08 подъезд был питч-огибающей фиксированной глубины: +3…5 полутонов
независимо от того, откуда приехали. Здесь стоит `glide` из prebake Switch
Angel — он считает интервал от предыдущей ноты и ставит `penv` сам:

```js
pdecay = glideT, penv = -12 * Math.log2(freqTo / freqFrom)
```

Три следствия:
- **интервал точный** — кварта, октава, b2: в проверке видно `+12`, `+6`, `-1`
  вместо всегдашних «четыре полутона снизу»;
- **слайд выборочный** — второй множитель это гейт на 16 шагов, поэтому
  съезжают две ноты в такте, а не все (иначе получается портаменто и линия
  «мылится»);
- **одна ручка вместо двух** — `acidGlide` (время) заменил `acidSlide` +
  `acidSlideTime`.

Грабля, на которой я сел: гейт надо писать **без** угловых скобок.
`<0 0 1 …>` — альтернация, один элемент на цикл, то есть гейт превращается в
константу (у меня линия то слайдила везде, то нигде, и по коду это не видно).
Голый список `0 0 1 …` — 16 шагов в такте. Вторая грабля: `getFrequencyFromValue`
есть в скоупе редактора, но не экспортируется из `@strudel/core` 1.2.6, поэтому
в функции стоит фолбэк через `noteToMidi` — иначе `verify` не пройдёт.

Проверки: 23 дорожки / 183 удара / 78 слайдеров, `tension` — трения нет
(31 намеренный тритон), `gains` / `doubles` / `modes` / `latch` — как в 08,
`live` — eval ок, 180px, ползунок = код.

`10-slowtrap.js` — **четвёртый характер** после дарк-техно и эйсида: 136 BPM,
но полутемповый ритм (удар и снейр через полтакта, между ними 32-е). Медленно
по ощущению, быстро по сетке. Собран по `docs/switchangel-recipes.md` — из неё
взят `glide` для 808 и общий принцип «одна ручка вместо трёх».

Что в нём:
- **808 — главный инструмент**, не «бас под бочкой»: синус `f1…c2` со слайдом
  между нотами (`glide`), срез 160 Гц, длинный хвост. Слайд 808 в трэпе — это
  и есть грув.
- **Эйсид берлинский, не кислотный**: тот же 303, но играет 6–8 нот на такт
  вместо 16 и низко (`f2…c3`) — он тут фактура, а не линия. `b` (b5) в каждом
  такте, это и делает его эйсидом.
- **Ритм сломан во всех четырёх режимах**: `0` трэп / `1` лом (`euclid(5,16)`,
  снейр уезжает на 2-ю долю) / `2` полутемп (бочка только на 1-й) / `3` дробь
  16-ми. Ни в одном режиме нет «четырёх в пол».
- **Бочка — два искажения подряд**: `shape` (вейвшейпер) и `distort` (клиппинг),
  плюс `speed(0.82)` — 909-бочка растягивается вниз.
- **Вокодер имитацией**: настоящего вокодера в движке нет (нужен носитель +
  модулятор), поэтому суперпила через `vowel` с бегущими гласными + `phaser` +
  `chorus`. Звучит как робот-хор.
- **Спецэффекты в сторону IDM, а не 90-х**: `ply`-роллы на 32-х, `degradeBy`,
  `coarse` на точках, `pressBy` (заикание), `nudge` (микротайминг), обратный
  свэлл, «лента» на неверной скорости. Больших холлов нет — длинные хвосты
  вместо комнат.

🛑 **Правило, которое теперь действует во всех новых треках: фильтр — сразу под
громкостью.** Это про **микшер, а не про цепь эффектов**, и про две вещи сразу:

1. **в объявлениях слайдеров** — `const kickVol = slider(...)`, следующей строкой
   `const kickCut = slider(...)`. Так играешь двумя пальцами: взял громкость,
   рядом крутанул срез. Порядок объявлений = порядок виджетов в коде, поэтому
   если срез объявлен на 40 строк ниже, он там и окажется — и играть неудобно.
2. **в цепи паттерна** — `.gain(...)`, следующей строкой `.lpf(...)`. На звук
   порядок не влияет (superdough собирает контролы в один объект и применяет
   эффекты в своём порядке), это правило читаемости.

Исключение — `.gain()` после `stut`/`echo`: они ПЕРЕЗАПИСЫВАЮТ громкость, так
что в 10 эха сделаны через `delay`, а не через `stut`.

🛑 **Бочка по умолчанию глухая.** Вадим: «я люблю прям глухо». Во всех новых
треках `kickCut` стартует около 300 Гц, а не 1100: верх бочки — не украшение,
а грязь, он спорит с хэтами и эйсидом. Если нужен щелчок — это ручка, а не дефолт.

### Веб-панель (`npm run web`) — микшер, тонкие настройки, настоящий редактор

Слайдеры в редакторе — это CodeMirror-виджеты: они узкие, их надо скроллить и
они врут после скролла. `web/` решает это, не отбирая редактор: **два столбца
сайдбара** (слева микшер — только громкости, в середине тонкие настройки
инструментов с коллапсерами) и **справа тот же CodeMirror, что на strudel.cc** —
с подсветкой, виджетами и Ctrl+Enter. Спектр — фиксом в правом нижнем углу,
вдвое меньше прежнего.

```bash
npm run web            # http://127.0.0.1:8080/
npm run web -- 9000    # другой порт
```

Сервер нужен потому, что панель тянет файл трека через `fetch` — с `file://`
браузер это запрещает.

Как это устроено (семь вещей, на которых всё держится):

1. **Редактор — настоящий.** `@strudel/codemirror` (`StrudelMirror`), тот самый
   пакет, из которого собран strudel.cc: он сам строит repl, сам рисует виджеты,
   сам делает eval. Своей копии кода у панели нет — она смотрит в тот же
   документ, что и редактор.
2. **Ручки — пульт от виджетов, а не отдельные сигналы.** Двигаешь ручку слева →
   панель делает ровно то же, что виджет под пальцем: меняет число в документе и
   шлёт `postMessage {type:'cm-slider', id, value}`. Отсюда звук меняется сразу
   (без перезапуска), код справа не врёт, и обратная сторона тоже работает:
   потянул виджет в редакторе — ручка слева поехала.
3. **Раскладка = дерево `instruments`.** Панель не хранит список ручек: она
   сканирует документ (`scanSliders`) и знает, какой `slider(` в какой ключ
   вложен. `vol` → микшер, всё остальное → тонкие настройки, группа и
   инструмент сворачиваются (`<details>`), состояние свёрнутости переживает
   eval. Новый ключ в дереве = новая ручка в панели, руками ничего не правим.
   Сканер идёт посимвольно и пропускает комментарии и строки: в шапке трека
   слово `slider(` встречается в прозе, и наивный поиск сбил бы нумерацию.
   **Подписи — оттуда же.** `name: 'Kick'` внутри инструмента — это не ручка,
   а имя для панели; словаря `INST_LABEL` в `panel.js` больше нет. Нет имени —
   подпись делается из ключа (`bodyLevel` → `body level`). Переключатели тоже
   без списка имён: признак структурный (глобальная ручка, `min 0`, шаг 1), а
   подписи кнопок — из строки-маркера в треке:
   `// @switches mode=stomp,gabber,break,half,roll harmony=fifths,minor`.
4. **Любой трек, а не один зашитый.** Меню в шапке собирается из `/api/tracks`
   (`tools/serve.mjs` читает папку `tracks/`), выбор трека пишется в хэш
   адреса (`#/tracks/techno/13-gabber-v3.js`) — ссылку можно дать другому.
   Заголовок и BPM в шапке берутся из самого файла, а не из константы;
   вкладка браузера называется статически — `STRUDEL EXTENSION`.
5. **Scenes / JSON — отдельная панелька над микшером.** Слева `INTRO` и
   `THEME`: пресеты объявляются в треке строкой
   `// @scenes {"intro":{...},"theme":{...}}`, ключи — пути дерева
   (`drums.kick.vol`) или имена глобальных ручек (`mode`, `harmony`). Справа
   `EXPORT` скачивает `{track, values, scenes}`, `IMPORT` ставит значения
   (и может заменить сцены). Нет `@scenes` — кнопки Intro/Theme выключены.
   Пример — `17-halfstep-dub-v2.js`.
6. **`sliderWithID` — свой.** Транспайлер превращает `slider(...)` в
   `sliderWithID(id, value, min, max)`. Штатный живёт в `@strudel/codemirror` и
   возвращает `ref` из другого инстанса `@strudel/core` (esm.sh грузит пакеты
   раздельно) — паттерн такой `ref` не понимает и звук умирает с
   `t is not a function`. Поэтому берём `ref` из того же `core`, что и паттерн,
   а значения храним сами. `evalScope(core, mini, tonal, wa, cm, {sliderWithID, slider})`
   — как `loadModules()` в strudel.cc.
7. **Мастер-цепь.** `BiquadFilter` (низ shelf 120 → середина peak 900 → верх
   shelf 5k) → громкость → анализатор: `output.destinationGain` отключается от
   `ctx.destination` и переподключается на нашу цепь. **Ручки эквалайзера сейчас
   скрыты** (не удалены: блок в `index.html` закомментирован, `bindEq()` тоже),
   фильтры стоят на 0 dB и ни на что не влияют. Вернуть = раскомментировать два
   места.

Четыре грабли, на которые уже наступили (чтобы не наступать снова):

- **`StrudelMirror` пишет на root инлайн-стили.** В конструкторе он ставит
  `background-color: var(--background); font-size: 18px; font-family: monospace`
  прямо в `style` контейнера. Инлайн сильнее любого нашего селектора, и это ровно
  два симптома: (а) непрозрачный фон перекрывал canvas визуализатора, (б) код
  рисовался 18px, хотя в CSS у `.cm-content` стояло 13px. Лечится после создания
  мира: `rootEl.style.backgroundColor = 'transparent'; rootEl.style.fontSize = '13px'`.
- **`getDrawContext()` без аргументов создаёт полноэкранный canvas.** Он ищет
  `canvas#test-canvas`, не находит, создаёт свой `position:fixed` во весь экран и
  вставляет первым в `body`. Создаёт его не наш код: `StrudelMirror` на каждом
  eval зовёт `cleanupDraw()`, а тот внутри делает ровно это. Сам canvas
  прозрачный (его только чистят), но в CSS панели правило `canvas { background: … }`
  красило и его — и он ложился чёрным **поверх шапки и левой панели** (они static,
  а canvas в positioned-слое), а редактор оставался виден только потому, что он
  `position:relative` и идёт в DOM позже. Снаружи выглядит как «страница чёрная,
  видно только код» — при идеальной геометрии в `getBoundingClientRect` и
  `elementFromPoint`. Лечится одной строкой: CSS красит только `#scope`, а не все
  `canvas` подряд. И `draw.getDrawContext('test-canvas')` при создании редактора —
  тогда `cleanupDraw()` находит наш canvas и не создаёт свой.
- **`defaultOutput`, а не только `onSchedule`.** Ядру нужен `defaultOutput`
  (`wa.webaudioOutput`), иначе `getTrigger` падает.
- **Банк сэмплов как у strudel.cc:** `dirt-samples` + `uzu-drumkit` +
  `tidal-drum-machines` + `aliasBank`. Без `uzu-drumkit` нет `sh`, `oh`, `rim` —
  трек играет, но три дорожки молча ругаются `sound not found`, и это слышно как
  пустые хэты. Синтезаторам нужен `registerSynthSounds()` в `prebake`.

**Визуализаторы — В КОДЕ, а не во весь экран.** В strudel.cc это block-widget
CodeMirror: метод в конце паттерна (`._pianoroll()`, `._punchcard()`,
`._pitchwheel()`, `._scope()`, `._spectrum()`), под которым прямо в редакторе
появляется канвас. На трек их бывает много — по одному на инструмент, и смотрятся
они именно в коде. В `12-slowtrap-v3.js` их шесть: дрон, 808, эйсид, колокольчики,
риз и хэты (`_punchcard`).

Как это устроено в пакете (и почему у нас заведено руками):

1. транспайлер видит вызов зарегистрированного метода и переписывает его в
   `._pianoroll('<id>')`, а в `meta.widgets` кладёт `{type, index, to}`;
2. после eval `StrudelMirror` зовёт `updateWidgets()`, `BlockWidget.toDOM()`
   достаёт элемент из реестра по `getWidgetID(cfg)` = `<id>_widget_<type>_<index>`;
3. метод паттерна сам создаёт canvas и кладёт его в реестр: `cm.setWidget(id, c)`.

`@strudel/codemirror` регистрирует эти методы на **своём** `Pattern.prototype`, а
под esm.sh это не тот инстанс ядра, на котором евал-ится трек (та же причина, по
которой понадобился свой `sliderWithID`). Поэтому `_pianoroll` / `_punchcard` /
`_pitchwheel` заведены руками в `web/panel.js`.

🛑 **Ловушка: `gain` = прозрачность.** `__pianoroll` рисует ноту с
`globalAlpha = velocity * gain` из значения hap'а. У нас `gain` — это ручка
громкости микшера, а ударные по умолчанию стоят в нуле: канвас на месте, нот не
видно (в пробе на нём оставалась одна линия плейхеда, 116 «зажжённых» пикселей =
1 px × 116 px высоты). Поэтому в витрину уходят копии hap'ов с `gain: 1`
(`vizHaps()` в `panel.js`). Звук при этом не трогаем: `_pianoroll` рисует «тень»
паттерна (`withHaps(...).tag(id)`) и возвращает исходный `this`, а `_punchcard` /
`_pitchwheel` вешают painter на играющий паттерн (`onPaint`) и правят `gain`
только внутри painter'а.

Ещё два следствия:

- **`_spiral` не заведён:** его функция рисования (`drawSpiral`) не экспортируется
  из `@strudel/draw`, поэтому перехватить haps и починить `gain` нельзя — на
  нулевой громкости он рисовал бы пустоту.
- **На самом strudel.cc наши роллы пустые, пока не поднята громкость** — там
  виджет штатный, и `gain` в нём честный. Это не поломка трека, а поведение
  движка; в нашей панели обойдено.

**В Node виджетов нет.** `npm run verify` падал на живом треке
(`._pianoroll is not a function`), потому что `@strudel/draw` в Node не грузится.
`tools/viz-stub.mjs` подставляет no-op, возвращающий паттерн, — его импортируют
`verify`, `gains`, `doubles`, `cpu`, `latch`, `modes`.

**Темы.** 39 схем из `@strudel/codemirror` (`cm.themes`), переключаются на живом
редакторе через `initTheme()`. Своя панель при этом остаётся лаймовой: тема
меняет только синтаксис кода. Лаймовые по духу — `strudelTheme` (дефолт, зелёно-
жёлтый синтаксис на #222) и `greenText` (зелёный по чёрному).

**Раскладка ручек — из дерева, без галок и эвристик.** Раньше группы собирались
по хвосту имени (`kickVol` / `kickCut` → БОЧКА) и это была эвристика: пропустил
суффикс в списке — получил сиротскую группу «KICKDIST». В 12 ручки лежат в
`instruments`, и панель читает вложенность как есть:

- `vol` любого инструмента → **левый столбец** (микшер), порядок = порядок дерева;
- всё остальное → **средний столбец**, `<details>` на группу и на инструмент,
  состояние свёрнутости переживает eval (`openState` в `panel.js`);
- `verb` и `duck` (объявлены вне дерева) → блок **Global** над микшером, туда же
  мастер-громкость панели (`#out`, это гейн ПОСЛЕ движка, не слайдер трека);
- `mode` и `harmony` → **панелька переключателей** между Global и микшером:
  у первого 4 положения, у второго 2;
- `// @scenes` → **панелька Scenes/JSON** над `main`: Intro/Theme ставят
  пресеты, Export/Import гоняют текущие значения и сцены через JSON.

Порядок левого столбца: `Global` (master, verb, duck) → переключатели →
громкости инструментов.

Внутри инструмента порядок — как в дереве, и `vol` там стоит первым, `cut` сразу
за ним: то же правило двух пальцев, что и в коде трека.

Горячие клавиши: `Ctrl+Enter` / `Ctrl+.` — их вешает сам `@strudel/codemirror`
(именно Ctrl, не Mod). На маке к ним добавлен `Cmd+Enter` / `Cmd+.`: слушатель
на `#root` в capture-фазе, только для `metaKey`, чтобы Ctrl остался за
редактором и двойного запуска не было.

Проверено в headless Chromium на 12: `105 knobs · playing`, микшер — 29 строк
(ровно столько инструментов с `vol`), тонкие настройки — 6 групп / 29
инструментов / 72 ручки, спектр 220×66 в 12 px от правого и нижнего края,
`eqVisible: false` (ручки EQ скрыты, цепь на месте), в `body` только

Драг ручки микшера пишет `vol: slider(0.42, …)`, драг ручки в тонком столбце —
`cut: slider(1500, …)` именно у Kick, кнопка MODE 2 пишет `const mode = slider(2`.

### Правило версий (жёсткое)

**Любая новая музыкальная идея — новый файл.** Хочешь другой бас, другой старт,
другие дефолты, другой характер бочки — это `05-…` / `02-berlin.js`, а не правка
предыдущего. Прошлый файл остаётся ровно таким, каким его слушали.

Править старый файл можно **только** когда он не работает: молчит дорожка,
слайдер откатывается, движок падает. Это не версия трека, это поломка —
сохранять её незачем.

Печатает, что реально попадает в сетку: номер доли, имя сэмпла или ноты.
Ловит опечатки в мини-нотации, несуществующие функции, пустые дорожки.
Плюс статические проверки, которые движок в node не заметит, а браузер — да:
строки мини-нотации в переменных без `m()`, `slider()` с не-числовым первым
аргументом, слайдеры, которые объявлены и нигде не читаются. Ещё одна строка —
`⚠ один сэмпл в одной позиции от разных дорожек`: это карта наложений, то,
что слышно как удар дважды.
Не ловит, как это звучит — для этого нужны уши.

**`npm run live` — это другой вопрос.** `verify` гоняет движок в node; он ничего не
знает про редактор. `live` открывает настоящий https://strudel.cc в headless
Chromium, вставляет файл, жмёт eval и печатает: есть ли паттерн, сколько слайдеров
в конфиге и сколько отрендерено, и не врёт ли ползунок после скролла. Нужен
локальный Chromium (или `CHROME=/path/to/chrome npm run live`). Пример вывода:

```
== tracks/techno/03-dub-v2.js (16946 символов) ==
  eval:        ок
  паттерн:     играет
  слайдеров:   64 в конфиге, 6 отрендерено (остальные за вьюпортом)
  слайдер:     драг 0 → 0.55; в коде "0.55", ползунок "0" ← РАССИНХРОН
```

`РАССИНХРОН` — это баг strudel.cc, а не трека (см. ниже и `docs/slider-bug.md`).

### `npm run tension` — где именно «шипит»

Слухом тритон ищется плохо: он может быть между мелодией и одной нотой пэда
в другой октаве, и на общем миксе это слышно как раздражение, а не как интервал.
Скрипт читает фразы из файла трека и считает интервалы:

- нота против **корня такта** — тритон (6 полутонов) в любой октаве;
- нота против **нот пэда этого такта** — тритон и малая секунда (1 полутон),
  но только в одной октаве: секунда через октаву уже краска, а не грязь.

Что нужно от трека: строка-маркер `// @roots c ab f bb eb g f ab` и пэд —
либо два (`PAD_A` / `PAD_B`), либо один `PAD`: у трека может быть одна укладка,
тогда режимы A и B просто совпадают (так в 10). Режим определяется суффиксом имени: `MEL_A`/`STAB_A`
сравниваются только с `PAD_A`, `MEL_B`/`STAB_B` — только с `PAD_B`,
всё остальное (общие партии) — с обоими. Это важно: сравнивать партию
с пэдом, который в этот момент не звучит, — значит находить несуществующие
конфликты.

Проверяется столько тактов, чтобы все фразы прошли полный дрейф против
гармонии (в 05 это 240). Малая нона НЕ флагуется: в Cm9 живут и b3, и 9.

**9-я — стиль, а не грязь.** Если 9-я (в C это `d`) образует тритон с нотой
пэда, чини **укладку пэда или место ноты во фразе**, но не выбрасывай 9-ю:
она и есть джазовый вкус. Пример из 05: `d5` в общей мелодии била в `ab3`
квартового пэда — убрал `ab3` из этого такта (`[eb3,bb3,f4]`), а 9-я осталась.
Второй приём: поставить 9-ю туда, где гармония её держит. Фраза длины 4 против
8-тактовых корней всегда попадает только на два корня (шаг 4) — первый такт
садится на `c`/`eb`, где `d` это 9-я или maj7, а на `ab`/`f` она была бы
тритоном. Так сделаны `MEL_B` и `TIA`.

### Диссонанс: намеренный vs случайный

Тулу всё равно, кто поставил тритон — ты или дрейф. Поэтому в 07 появился
маркер **`// @dark`**: он разрешает тритоны только **якорным** фразам, чья
длина кратна числу корней. Логика: если фраза всегда садится на известный
такт, тритон в ней — решение автора. Если фраза дрейфует (7, 5, 12 тактов
против 8), тритон всплывает каждый цикл в новом месте — это уже грязь, и она
остаётся ошибкой.

```
✓ STAB_A (8 такт., режим A)  ⚠ намеренных тритонов: 2
…
трения нет (намеренных тритонов: 6)

намеренные (якорные фразы, @dark):
  ORGAN  такт 1/8: g3 vs db4 — тритон (режим A)
  STAB_A  такт 1/8: gb4 — тритон к корню c
```

Малая секунда (ровно 1 полутон в одном регистре) остаётся ошибкой всегда:
это не тьма, а каша. Тритоны считаются по позиции внутри цикла, а не по
абсолютному такту — иначе один и тот же приём засчитывался бы заново каждые
8 тактов (было «120 мест» там, где их шесть).

## Грабли движка (проверено на 1.2.6)

- **🛑 `shape`, `crush`, `coarse`, `distort` и `ftype("ladder")` — это worklet
  на КАЖДОЕ событие.** В superdough они не нативные ноды: `getWorklet()` каждый
  раз делает `new AudioWorkletNode` и никогда его не переиспользует (biquad-
  фильтры, наоборот, берутся из пула `getNodeFromPool`). Создание worklet —
  самая дорогая операция в движке, и цена слоя считается так:

  **событий в такт × worklet'ов в цепочке × тактов в секунду**

  В первой версии `08-dark-acid.js` это давало ~180 worklet'ов на такт; при
  180 BPM это 0.75 такта в секунду, то есть **~135 конструкторов в секунду**,
  и звук захлёбывался. Виновником был не реверб, не винил и не дрон: `shape(0.3)`
  висел на хэтах, а хэты — 58 событий в такт (пять веток режимов, и ветки
  с `gain = 0` тоже строят граф — раннего выхода по нулевой громкости в
  `superdough()` нет). Плюс у эйсида в цепочке было `ladder + shape + crush`,
  три worklet'а на каждую из десяти нот, в трёх слоях.

  Лечение: worklet только там, где событий мало. Хэты, ролл и сирена — без
  `shape` вообще; эйсид — один `ladder` (грязь даёт `drive`, он перегружает
  сам фильтр); `shape` + `crush` — на слой крика и клэп; `ftype("24db")`
  вместо ladder везде, где не нужен характер. Стало 37 на такт (28/с), почти
  впятеро меньше, звук тот же.

  Считать это на глаз не надо: **`npm run cpu -- <файл>`** прогоняет трек через
  движок, складывает worklet'ы по фактическим событиям (8 тактов, чтобы
  дорожка, входящая позже, тоже попала) и печатает по каждому режиму — на такт
  и в секунду. Ориентир: до ~150/с живёт спокойно, 300+ начинает рвать звук.
  Замеры: `07` — 15/такт (8/с), `08` — 37 (28/с), `10` — 18–33 (10–19/с),
  `11` — 31–46 (18–26/с).
- **🛑 Ноль на ручке — не бесплатно. Гейт `.filter(audible)`.** Продолжение
  предыдущего пункта: раннего выхода по `gain = 0` в `superdough()` нет, поэтому
  заглушённая дорожка всё равно грузит сэмпл, строит узлы и worklet'ы, отдаёт
  сигнал в орбиту, дилей и реверб — и только потом умножает на ноль. А у нас
  по умолчанию ВСЕ ударные стоят в нуле, и вдобавок в каждом стеке четыре ветки
  режима, из которых три всегда с `gain = 0`.

  Замер в живом движке (6 секунд, ручки в дефолте, считаются конструкторы
  `AudioWorkletNode`, `createBufferSource`, `createGain`):

  | | worklet | buffer source | gain-нода |
  |---|---|---|---|
  | без гейта | 238 | 451 | 2861 |
  | с гейтом | 6 | 6 | 63 |

  Остаток — атмосфера (воздух, дрон, песок), у них дефолт не ноль.

  Поэтому каждая дорожка в `11-slowtrap-v2.js` кончается `.filter(audible)`:
  hap с `gain <= 0.001` не доходит до триггера вообще. Заодно исчезают
  неактивные ветки режимов: **180 событий в такт → 83** при поднятых ручках
  (`npm run verify`), а `npm run cpu` теперь показывает настоящую нагрузку —
  раньше он считал только звучащие события, то есть занижал её.

  Два условия, без которых гейт ломает:
  - **тип проверяется** — если `gain` пришёл не числом (сигнал/паттерн), дорожку
    не глушим, иначе однажды молча выключится живая;
  - **гейт стоит ПОСЛЕ `._pianoroll()`** — виджет рисует «тень» паттерна,
    снятую до фильтра, поэтому ролл показывает ритм и на нулевой громкости
    (`_punchcard`/`_pitchwheel` для этого спрашивают свой, незагейченный
    паттерн — см. `ownHaps()` в `web/panel.js`).

  Инструменты, которые смотрят на сетку (`verify`, `doubles`, `modes`, `cpu`,
  `latch`), теперь принудительно поднимают громкости до 0.8 — `tools/loud.mjs`.
  Иначе с гейтом они видели бы пустоту: трек-то стартует тихо. `gains` наоборот
  остаётся на нулях — он ровно за тем и нужен.

  🛑 **Такты и доли не путать.** 180 BPM — это 3 доли в секунду, но 0.75 такта:
  в такте четыре доли. Бюджет считается в тактах в секунду, иначе цифра
  завышается вчетверо — на этом я и ошибся в первом разборе.
- **🛑 `vowel` не паттернится — слой молча умирает.** `vowel(m("<a e i o u>"))`
  даёт `vowel: unknown vowel Object` на каждом событии и НИЧЕГО не звучит, при
  этом код читается нормально, `verify` зелёный и `live` тоже: оба смотрят на
  паттерн, а ошибка живёт в superdough, на уровне события. Проверено в живом
  редакторе 13.11.26: `vowel("a")` и `vowel("<a e i o u>")` чисто, `m(...)` —
  ошибка. Гласные — только mini-строкой. Общий вывод: если дорожка «есть в коде,
  но её не слышно» — открывай консоль браузера, `hasPattern` этого не покажет.
- **🛑 Полосы: пэд в регистре линии — это малая секунда, а не «плотность».**
  Когда 303-линию в 08 опустили на октаву (в `a2…c4`), `tension` тут же дал
  24 места трения: `eb3` линии против `e3` пэда, `c3` против `db3`. Причина
  не в нотах, а в том, что пэд стоял ровно в регистре линии. Лечение —
  развести слои по полосам и держать это правило при любой правке регистра:
  бас `a1…f2` (55–87 Гц) · линия `a2…c4` (110–260) · пэд `a3…g4` (220–390) ·
  стаб до `c5`. Пэд и стаб поднялись на октаву, у стаба `bb3` стало `bb4`,
  у хувера на bb-тактах убрана терция (`db4` била в `c4` пэда) — и трения
  нет. Заодно: малая секунда «прощается», только если это короткий удар
  (стаб 160 мс), а не выдержанный слой.
- **🛑 `stut()` и `echo()` ЗАТИРАЮТ `gain`, а не умножают его.** Внутри они
  делают `pat.gain(pow(feedback, i))` — то есть ставят громкость заново:
  первая копия получает `1.0`, дальше `0.55`, `0.30`, `0.17`. Всё, что ты
  выставил в `.gain(...)` раньше в цепочке, забыто. Отсюда «слайдер громкости
  в ноль, а щелчки слышно»: у дорожки `клики` в 05 четверть ударов играла на
  полной громкости мимо `clapVol`. Лечение — свой стутер, который УМНОЖАЕТ:

  ```js
  const stutGain = (times, fb, step) => (x) =>
    x.echoWith(times, step, (p, i) =>
      p.withValue((v) => ({ ...v, gain: (v.gain ?? 1) * Math.pow(fb, i) })),
    )
  // … .sometimesBy(0.25, stutGain(4, 0.55, 0.03125))
  ```

  Ритм и затухание те же (`echoWith` — это и есть внутренность `stut`), но
  громкость слоя сохраняется. Проверено: при `clickVol = 0.5` копии идут
  `0.500 / 0.275 / 0.151 / 0.083`, при `0` — полная тишина. `verify` теперь
  ставит ⚠ на цепочку `gain(...) → stut/echo`, а `npm run gains` проверяет
  это на слух-без-слуха: гоняет трек со всеми громкостями в нуле и ищет
  дорожки, которые всё равно звучат.
- **`slider()` — только виджет редактора.** Он возвращает непрерывный сигнал,
  поэтому живыми могут быть только параметры паттерна (`gain`, `lpf`,
  вероятности). `setcpm(slider(...))` живым НЕ будет — темп читается один раз
  при запуске. Темп меняется правкой числа + `Ctrl+Enter`.
- **`"1 2".mul(150)` из документации не работает** — `String.prototype.mul`
  не существует. Правильно наоборот: `hatVol.mul("[1 .35 .6 .35]*4")`.
- **`degradeBy` / `sometimesBy` съедают событие в нулевой позиции — при ЛЮБОМ
  аргументе, не только 0.** `rand` в `t=0` равен 0, а условие «оставить» —
  `rand >= x`, то есть первый удар выбрасывается всегда. Поэтому бочка в 01
  разбита на две дорожки, а не глушится вероятностью, и поэтому у дорожки
  `клики` в `02-dub` первый такт может быть пустым — это не поломка.
- **🛑 `every(n, f)` срабатывает на НУЛЕВОМ такте.** `every(4, x => x.ply(2))`
  на хэтах означает: первый же такт, который ты слышишь после `Ctrl+Enter`,
  уже идёт дробью — в 01-berlin это давало 74 события в такте 0 против 40 в
  такте 1 (32-е вместо 16-х), и это слышно как «играет дважды». Если дробь
  нужна на 4-м такте, а не на первом — `lastOf(4, x => x.ply(2))`
  (срабатывает на 3-м, 7-м, 11-м). В `02-dub` так и сделано.
- **Защёлка переключения на границе фразы — `seg`.** `harmony.seg(1/8)` даёт
  сигнал, который сэмплируется один раз в 8 тактов: двинул слайдер — значение
  подхватится только на следующей границе, начатая фраза доиграется. Проверено:
  слайдер двинут на 3.5-м такте → переключение на 8-м (такты 0–7 старый режим,
  8+ новый). Плюс `gain` читается в момент удара, поэтому уже звучащий аккорд
  доигрывает в любом случае. Так сделан переключатель атонал ⇄ джаз в
  `03-dub-v2`: два пэда и два стаба, у каждого свой гейт `hAtonal` / `hJazz`.
- **Дубли ловятся не на слух, а сеткой.** `npm run doubles -- <файл>` печатает
  по каждой дорожке события такта 0 и такта 1: если в такте 0 их больше —
  что-то стреляет только на старте. Плюс карту «позиция:сэмпл → дорожки»:
  один сэмпл в одной позиции от двух разных дорожек = удар дважды. Именно так
  нашлось, что в `01-berlin` бочка и румбл — обе `s("bd")` в 0, 4, 8, 12.
  Вариант сэмпла учитывается: `hh` и `hh:2` — разные звуки, не дубль.
  События с `gain = 0` в карту не попадают: это выключенная ветка режима,
  а не удар (иначе в 06 ловился фантом «призрак снейра + филл» — они совпадают
  по позиции, но никогда не звучат в одном такте).
- **🛑 Группа в мини-нотации занимает ОДИН слот.** `"~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ ~ [sd*8]"`
  — это не «12 пауз и ролл на последнюю долю», а **13** элементов: скобка — один
  элемент, поэтому такт делится на 13, и удары приезжают в 14.77, 14.92…
  вместо 12, 12.5, 13. Считать элементы надо по пробелам верхнего уровня.
  Ролл на последнюю долю — это `[sd*2] [sd*2] [sd*2] [sd*2]`: четыре элемента
  по 16-й, внутри каждой две 32-е. Именно так поймался филл в 06 — сетка
  `verify` показала 14.769 вместо 12.
- **Режим — это не только рисунок, но и его отсутствие.** `npm run modes -- <файл>`
  прогоняет трек по каждому значению `mode` и печатает, сколько ударов даёт
  каждая дорожка в каждом режиме, плюс подпись (позиция + сэмпл + громкость),
  чтобы «прямо» и «брейк» не выглядели одинаково при равном числе ударов.
  Громкости внутри проверки принудительно поднимаются до 0.8 — в 05/06 они
  стартуют с нуля, иначе таблица была бы из одних нулей; сам файл не меняется.
  `verify` этого не видит: он гоняет только дефолтный `mode = 0`, и ветки
  остальных режимов для него — события с `gain = 0`.
- **Защёлка проверяется, а не предполагается.** `npm run latch -- <файл>`
  подменяет `const harmony = slider(...)` на сигнал, который равен 0 до 4-го
  такта и 1 после, и печатает, какие дорожки реально сменили состояние и на
  каком такте. В 07 это пэды, стабы и переключаемые мелодии — все на такте 8,
  хотя слайдер двинули на 4-м. Строки, которые меняются на другой границе
  (шумовой свип раз в 16 тактов), подписаны «не harmony — свой цикл», чтобы
  не выглядели подтверждением.
- **🛑 `phrase([...])`: каждый такт — в скобках.** `phrase` собирает
  `m('<…>')`, а `<…>` альтернирует по элементам **верхнего уровня**, то есть по
  пробелам. `'a3 a3 ~ a4'` внутри `<…>` — это не «четыре шага в такте», а
  четыре элемента альтернации: по одному на такт. В 08 из-за этого эйсид-риф
  играл одну ноту за такт вместо шестнадцати, а стаб вообще молчал (первым
  элементом шла `~`). Правильно — `'[a3 a3 ~ a4]'`, скобка делает такт одним
  элементом. `verify` это видит сразу: в сетке дорожки одна позиция вместо 16.
- **`penv` / `panchor` — питч-огибающая, и она работает** (в `@strudel/core`
  есть все контролы: `penv`, `pattack`, `pdecay`, `psustain`, `prelease`,
  `pcurve`, `panchor`). Устроена она не так, как ожидается: в superdough
  `min` = питч в НАЧАЛЕ атаки, `max` = в КОНЦЕ, а `panchor` сдвигает обе
  границы и **по умолчанию равен `psustain`** (а `psustain` по умолчанию 1):
  - `panchor(1)`, `penv(4)`: старт на 4 полутона НИЖЕ, подъём занимает
    `pattack`, дальше стоит на ноте. Это 303-подъезд — и время подъезда
    задаётся именно `pattack`, а не `pdecay`.
  - `panchor(0)`, `penv(12)`, `pattack(0.001)`, `psustain(0)`: мгновенный
    прыжок на 12 вверх и спуск к ноте за `pdecay`. Это хувер.
  Отсюда грабля: `pattack(0.001)` при `panchor(1)` не даёт подъезда вообще —
  нота встаёт на место за миллисекунду, и кажется, что `penv` «не работает».
- **Контрол сэмплируется в момент удара.** Поэтому `.lpf("<200 900>")` на одной
  длинной ноте даст один скачок за такт, а не плавный свип. Чтобы фильтр двигался
  *внутри* ноты, нужен LFO: `lpdepth` + `lpsync`. Подробнее — `docs/references.md`.
- **Длину ноты задаёт вес `@`.** `note("bb1 c2 f1@1.5 ~@0.5").slow(4)` — такт,
  такт, полтора такта ноты и полтакта паузы. Проверяется `queryArc`: `0+1 1+1 2+1.5`.
- **`release` — единственный способ дотянуть ноту.** Отпускание всегда идёт *после*
  конца события, поэтому «последние полтакта тает» = событие короче на полтакта
  плюс `release` на полтакта. `lpr` (фильтр) закрывается синхронно с ним.
- **Огибающая фильтра — в секундах, не в долях.** `lpa` / `lpd` / `lpr` — секунды,
  `lpsustain` — 0..1. Полтакта на 174 BPM = 0.69 с; в v4 это считается от темпа
  (`barSec / 2`), чтобы не разъезжалось при смене BPM.
- **🛑 Строка мини-нотации в переменной НЕ парсится.** Транспайлер REPL оборачивает
  в `m()` только строковые литералы; строку, лежащую в переменной, он не видит.
  `const BASS = "c2 ~ c2 ~"` + `note(BASS)` = одна «нота» из всего текста, то есть
  тишина. Лечится явным `m()`: `const BASS = m("c2 ~ c2 ~")`. `npm run verify`
  статически ловит такие переменные, печатает `✗ строки в переменных без m()`
  и падает с ненулевым кодом.
- **🛑 `slider()` принимает только числовой литерал.** ID слайдера —
  `slider_<смещение первого аргумента>`, а значение виджета берётся из
  `node.arguments[0].raw`. У выражения (`slider(halfBar, …)`) `raw` нет → значение
  `undefined`, перетаскивание падает на `originalValue.length`, а при следующем
  запуске слайдер откатывается к тому, что написано в коде. Только числа.
  `npm run verify` ловит такое (`✗ первый аргумент не число`) и падает.
- **Значения слайдеров живут в тексте кода.** `sliderWithID` при каждом запуске
  делает `sliderValues[id] = <значение из кода>`, а перетаскивание переписывает
  число прямо в тексте. Поэтому «слайдер не слушается» лечится `Ctrl+Enter`:
  состояние пересоберётся из кода.
- **🛑 Ползунок откатывается после скролла и может испортить код — это баг
  strudel.cc, не наш.** `toDOM()` ставит ползунок на значение, застывшее с
  последнего `Ctrl+Enter` (`this.value`), а `eq()` возвращает `false`, поэтому
  DOM-узел пересоздаётся при каждом пере-рендере. Дальше драг считает длину
  заменяемого числа от старого значения: `0.55` + драг → `0.8.55` → `SyntaxError`.
  Звук при этом правильный (живое значение в `sliderValues`), врёт только
  ползунок. Правило: **перед драгом — `Ctrl+Enter`; выглядит сброшенным — не
  тяни, сначала `Ctrl+Enter`; не скроллить во время игры.** Разбор с выводом
  теста — `docs/slider-bug.md`.
- **Ширина слайдера — 64px инлайном, перебивается `!important`.** В `toDOM()`
  стоит `style="width:64px"` без `!important`, поэтому `.cm-slider input
  { width: 180px !important }` работает (замерено: 160 и 180 — вёрстка не едет,
  320 — строки лезут вправо). Ставить либо строкой в файле трека (`document`
  в eval доступен), либо снаружи через Stylus. Точные значения удобнее не мышкой,
  а `←`/`→` на сфокусированном слайдере: ровно один шаг и не попадает в баг
  с длиной числа. Детали — `docs/slider-bug.md`.
- **Рандом на ноту — это `rand`.** Он непрерывный, но контрол читается один раз на
  удар, поэтому `lpenv(rand.range(2.4, 3.6))` даёт своё значение каждой ноте.
  В v4 поверх слайдера: `jit(amt)` = множитель `1 ± amt`, так что живой контроль
  остаётся, а повторы фразы не одинаковые.
- **`<a b c …>` с N элементами = N тактов.** Так пишутся длинные фразы. Переносы
  строк внутри мини-нотации — просто пробелы, поэтому фразу можно расписать по
  строке на такт: в `techno/01` это делает хелпер `phrase([...])` = `<` + join + `>`.
- **`fm()` есть, но значение лежит в поле `fmi`.** Так в доках и написано: `fm` —
  синоним `fmi`. `.fm(2)` работает (FM-колокольчик в `techno/01`), просто не ищи
  `fm` в `hap.value`. `fmh` — гармоничность: нецелая (2.41) даёт металл, целая —
  певучесть. `fmdecay`/`fmsustain` — огибающая индекса: удар яркий, хвост тусклый.
- **`transpose` в 1.2.6 нет.** Транспонировать — через `.add(note("12"))`;
  `.add(12)` на нотном паттерне падает с `Can't do arithmetic on control pattern`.
- **`.every(n, f)`** срабатывает на каждом n-м такте (проверено: `every(3)` → такты
  0, 3, 6). Так делается «лом» без расписанной аранжировки.
- **Гасить слои лучше гейном, а не `mask`.** `.gain(vol.mul(modeOn(k)))` с
  `modeOn = mode.fmap(m => m === k ? 1 : 0)` работает железно и переключается на
  лету — так сделаны три режима барабанов в `techno/01`.

## Палитра эффектов (что реально есть в 1.2.6)

Проверено перебором экспортов `@strudel/core`, чтобы не изобретать имена:

- `crush(1…16)` — биткраш, 1 = злой, 16 = почти чисто. `coarse(2…)` — грубее,
  но работает только в хромиум-браузерах.
- `shape(0…1)` — вейвшейпер (мягкое ограничение, «жир» без цифровой рвани),
  `distort("amount:postgain:type")` — клиппинг с выбором типа (`diode` и др.),
  громкий: постгейн лучше ставить сразу. Порядок в цепочке не важен — движок
  применяет их в фиксированном порядке, и каждый срабатывает один раз.
- `drive(x)` — подгруз фильтра, **только для `ftype("ladder")`**. Внутри это
  `exp(x)`: `0.69` (дефолт) ≈ усиление 2, `1` ≈ 2.7, `2.6` ≈ 13. Перегружается
  сам фильтр на резонансе — это и есть «шершавость» 303, отдельно от `shape`.
- `penv` / `pattack` / `pdecay` / `psustain` / `pcurve` / `panchor` — питч-
  огибающая. Ею делаются 303-подъезды и хувер, семантика — в граблях выше.
- `stut(times, feedback, time)` — стутер: `stut(4, 0.55, 0.03125)` = 4 повтора
  на 1/32. `echo` — то же, но без затухания по гейну.
- `vowel("<a e o u>")` — формантный фильтр, аккорд начинает «говорить».
  `chorus(0…1)` — ширина. `jux(f)` — две копии влево/вправо. `chop(n)` /
  `striate(n)` — резать сэмпл.
- `lastOf(n, f)` / `firstOf(n, f)` — применить к последнему/первому из n тактов.
  `when(cond, f)` — по условию от номера такта. `struct("x ~ x ~")` — ритм-маска.
- `sometimesBy(p, f)`, `sometimes` / `often` / `rarely` / `almostAlways` /
  `never`, `degradeBy(x)` — рандом. `brand`, `perlin`, `irand`, `wchoose`,
  `choose` — рандом-сигналы и выбор из списка.

## Если git не может записать index

В этой папке (`~/Local Docs`) git умеет **создавать** lock-файлы, но не может их
**удалить**: `unable to unlink '.git/index.lock': Operation not permitted`. Сам `rm`
из шелла тот же файл удаляет без проблем, то есть это не права, а то, как git
делает unlink.

Отсюда два следствия, оба выглядели как «в репозитории уже крутится другой git»:

- `git status` тоже пишет `.git/index.lock` (обновляет stat-инфо) и оставляет его
  после себя → следующая команда падает с `File exists`;
- `git commit` оставляет `.git/HEAD.lock` и `.git/refs/heads/master.lock`, после
  чего репозиторий «залочен» навсегда, хотя никакого процесса нет.

Лечится так:

```bash
# 1. чтение — без lock-ов вообще
GIT_OPTIONAL_LOCKS=0 git status
GIT_OPTIONAL_LOCKS=0 git log --oneline

# 2. запись — индекс в /tmp + сначала убрать все протухшие lock-и
find .git -name "*.lock" -delete
cp .git/index /tmp/idx
GIT_INDEX_FILE=/tmp/idx git add -A
GIT_INDEX_FILE=/tmp/idx git commit -F msg.txt
cp /tmp/idx .git/index          # вернуть индекс на место
```

`cp` перезаписывает файл по содержимому, без unlink/rename — поэтому проходит.
Признак, что дело именно в этом: в ошибке `File exists`, а `ls .git/*.lock`
показывает файл, которого «не должно быть».

## Почему `patch-strudel.mjs`

Опубликованный `@strudel/core` тянет `@kabelsalat/web` (браузерный REPL) и падает
в node на импорте. Патч подменяет его заглушкой; запускается автоматически
из `postinstall`. Если `npm install` делали с `--ignore-scripts` — запусти
`node tools/patch-strudel.mjs` руками.

## Добавить трек

Копируешь любой файл из `tracks/`, меняешь `$:`-дорожки, гоняешь `npm run verify`.
Каждый `$:`-блок — отдельная дорожка; комментарий над ним печатается как имя.
