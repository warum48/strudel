This page is a UI extension for Strudel: a live-coding editor plus a control surface (mixer, tone controls, switches, scenes, timeline) that is generated from the track source itself. Nothing is configured by hand — if a track follows the conventions below, the whole UI appears automatically.

The panel does not store track metadata. It reads your .js track, finds sliders and a small set of marker comments, and builds the interface from them. That is why a track that “looks fine” can still have an empty UI: the shape of the code matters.

Quick start

npm run web                 # http://127.0.0.1:8080/
# put a file into tracks/<genre>/<name>.js
# choose it in the top-left dropdown, press PLAY, then Ctrl+Enter

The server is a plain static file server. It also exposes /api/tracks, so any .js under tracks/ shows up in the dropdown automatically.

Downloaded reference scripts live in refs/strudel/ (git-ignored, see refs/strudel/INDEX.md). Playable files from there appear in the same dropdown below a “REFS” delimiter; loading and playing them works exactly like our own tracks.

The track contract

A track that gets the full UI needs four things:

  1. const instruments = { ... } — the mixer/tone tree.
  2. Top-level slider(...) calls — global knobs and switches.
  3. Optional marker comments — @switches, @scenes, @mutes.
  4. Optional const TIMELINE = [...] — the arrangement view.

1. Instruments and groups

The const must be named exactly instruments. Groups are keys at two spaces, instruments at four, parameters at six. Every parameter must be on its own line, and each instrument must have a name and a vol. 

const instruments = {
  drums: {
    name: 'Drums',
    kick: {
      name: 'Kick',
      vol: slider(0.4, 0, 1, 0.01),      // mixer row
      cut: slider(180, 60, 4000, 10),    // tone panel
      decay: slider(0.3, 0.05, 1, 0.01),
    },
    hat: {
      name: 'Hats',
      vol: slider(0.2, 0, 1, 0.01),
      cut: slider(9000, 800, 16000, 100),
    },
  },
  low: {
    name: 'Low',
    bass: {
      name: 'Bass',
      vol: slider(0.5, 0, 1, 0.01),
      cut: slider(80, 40, 220, 1),
    },
  },
}
const { drums, low } = instruments
Do not write instruments inline on one line (kick: { name: 'Kick', vol: slider(...) }). The scanner walks line structure and will miss those sliders.

Wire every parameter into sound; otherwise the knob is dead:

$: s('bd')
  .gain(drums.kick.vol)
  .lpf(drums.kick.cut)
  .decay(drums.kick.decay)

vol becomes the mixer volume and the Mute/Solo target. All other parameters appear in the Tone column, grouped by group and instrument.

2. Sliders, globals and switches

A slider is a normal Strudel slider: slider(value, min, max, step). The first argument must be a numeric literal — the panel rewrites that literal when you drag, so expressions are not supported. 

const verb = slider(0.4, 0, 1, 0.01)   // global knob (no instruments.* path)

A top-level slider with min: 0 and step: 1 is drawn as a switch. Give it labels with a marker; the marker key must match the variable name: 

// @switches mode=boom,break,half,roll harmony=quartal,ninth bass=user,roll
const mode = slider(0, 0, 3, 1)
const harmony = slider(0, 0, 1, 1)
const bass = slider(0, 0, 1, 1)

Values are indices (0, 1, 2…). Use them to pick patterns: 

const words = note('e2 e2 f2 g2')
const picked = mode.pick([
  m('x ~ x x ~ x x ~'),
  m('~ x x ~ x ~ x x'),
])
$: s('bd').struct(picked)

// or gate layers:
const leadOn = harmony.fmap((v) => (v === 1 ? 1 : 0))
.gain(keys.lead.vol.mul(leadOn))

3. Scenes

Scenes are presets for knob values. They live in a comment as JSON. Paths are either a top-level slider name or group.instrument.param. 

// @scenes {"intro":{"mode":2,"harmony":0,"drums.kick.vol":0,"low.bass.vol":0.2},"theme":{"mode":1,"harmony":1,"drums.kick.vol":0.4,"low.bass.vol":0.5}}

The scene buttons write those values into the document and re-evaluate the track. EXPORT downloads the current slider state in the same format.

4. Mutes

M and S exist for every instrument with a vol; they are handled by the panel (base volume is kept, the engine receives an effective value). No track code is needed.

G is a group mute. Declare it in a marker and link instruments to it with a mute field: 

// @mutes muteDrums,muteKeys
const muteDrums = slider(0, 0, 1, 1)
const muteKeys = slider(0, 0, 1, 1)
const onDrums = muteDrums.fmap((v) => 1 - v)

// inside the instrument:
kick: {
  name: 'Kick',
  mute: 'muteDrums',
  vol: slider(0.4, 0, 1, 0.01),
}

// wire it:
.gain(drums.kick.vol.mul(onDrums))
G-mutes are separate from M/S and are written into the document (0/1), so they also survive re-evaluation.

5. Timeline

The timeline is optional. It is shown when the track contains a literal const TIMELINE = [...]. Sections are contiguous, measured in bars, and values are multipliers applied to gains (or to any parameter you choose). 

const TIMELINE = [
  { at: 0,  len: 8,  name: 'INTRO', values: { kick: 1, bass: 0, pad: 1 } },
  { at: 8,  len: 16, name: 'DROP',  values: { kick: 1, bass: 1, pad: 1 } },
  { at: 24, len: 8,  name: 'OUTRO', values: { kick: 0, bass: 0, pad: 1 } },
]
const TL_TOTAL = Math.max(...TIMELINE.map((s) => s.at + s.len))

const tlCurve = (key) => {
  let last = 0
  const segs = []
  for (let i = 0; i < TIMELINE.length; i++) {
    const sec = TIMELINE[i]
    if (Object.prototype.hasOwnProperty.call(sec.values, key)) last = sec.values[key]
    const next = i + 1 < TIMELINE.length ? TIMELINE[i + 1].at : TL_TOTAL
    if (next - sec.at > 0) segs.push([next - sec.at, pure(last)])
  }
  return arrange(...segs)
}

// use it in gains:
.gain(drums.kick.vol.mul(tlCurve('kick')))

The panel draws the sections, lets you edit levels in the inspector, and re-evaluates on APPLY. LOOP loops the arrangement; STOP stops playback.

6. LOOP / SONG

A common pattern is a song switch that bypasses the timeline in LOOP and uses it in SONG: 

// @switches song=loop,song
const song = slider(0, 0, 1, 1)
const songGate = song.fmap((v) => (v > 0.5 ? 1 : 0))
const loopGate = song.fmap((v) => (v > 0.5 ? 0 : 1))
const tlOr = (key, loopLevel = pure(1)) =>
  tlCurve(key).mul(songGate).add(loopLevel.mul(loopGate))

.gain(drums.kick.vol.mul(tlOr('kick')))                    // 1 in LOOP
.gain(vox.quote.vol.mul(tlOr('vox', pure(0))))             // off in LOOP

7. Samples

Load sample maps only in the browser, so headless checks still run: 

if (typeof samples === 'function') {
  samples({
    bd: ['bd/11_bd_mot4i.wav'],
    hh: ['hh/10_hh_switchangel.wav'],
  }, 'https://cdn.jsdelivr.net/gh/tidalcycles/uzu-drumkit@main/')

  // local files under samples/ are served by the same static server:
  samples({ quote: ['samples/de-quote/kafka.wav'] }, './')
}

Prefer jsDelivr or local files over raw.githubusercontent.com: raw GitHub returns 503 often enough to look like “some samples do not load”.

Debugging an empty UI

  • Open the browser console and look for panel: N slider( … M widgets — a mismatch means the source scanner lost a slider.
  • Check that instruments is spelled exactly and objects are multi-line.
  • Check that every @switches key matches the slider variable name.
  • Check that TIMELINE is a literal array (no spreads, no helper calls inside it).
  • If the UI works but the sound is silent, check mute/solo, vol, and timeline values.

Optional headless checks

npm run verify  -- tracks/techno/22-dark-trance-160.js
npm run tension -- tracks/trip-hop/02-acid-jazz-v2.js
npm run doubles -- tracks/techno/22-dark-trance-160.js
npm run cpu     -- tracks/techno/22-dark-trance-160.js

These scripts are optional. They check parseability, harmonic friction, duplicate hits and worklet load — useful, but the track is not required to pass any particular style rule.
